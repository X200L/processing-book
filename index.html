Введение в Processing

Processing удобен тем, что результат кода видно почти сразу: написал несколько строк, запустил скетч и уже видишь окно, фигуру или анимацию. Поэтому здесь проще понять не только синтаксис, но и саму логику программы: что выполняется один раз, что повторяется каждый кадр и как данные превращаются в изображение.

Processing используется студентами, художниками, дизайнерами и исследователями для изучения программирования, прототипирования и создания визуальных проектов. Его главное преимущество — минимальный порог входа: вы можете нарисовать первую фигуру буквально в трёх строках кода.

Зачем изучать Processing?

• Визуальная обратная связь — результат каждой команды виден сразу на экране.

• Простой синтаксис — основан на Java, но гораздо дружелюбнее к новичкам.

• Широкие возможности — от простых рисунков до сложной анимации и взаимодействия с внешними устройствами.

• Активное сообщество — тысячи примеров и библиотек.

Связь с Arduino

Если вы уже знакомы с Arduino, то заметите много общего. Это не случайно: именно Processing послужил вдохновением для создателей Arduino. Среда разработки Arduino IDE построена на основе Processing IDE, а язык Wiring (на котором пишут для Arduino) основан на Processing.

Подробное руководство по подключению и совместной работе — в главах 20 и 21 этого учебника.

Установка и настройка

В этой главе задача простая: установить Processing 4 и разобраться, где писать код, где смотреть ошибки и как запускать скетч. Не пытайтесь запомнить весь интерфейс сразу. На старте достаточно уверенно находить редактор, консоль, Run и Stop.

Шаг 1: Скачивание

• Перейдите на официальный сайт Processing (https://processing.org/download/) и скачайте версию для вашей операционной системы.

Шаг 2: Установка

• Windows: запустите установщик .exe.

• macOS: откройте .dmg и перетащите Processing в папку Программы.

• Linux: распакуйте архив и запустите файл processing.

Шаг 3: Запуск

Запустите приложение. Перед вами откроется редактор с пустым файлом:

  [ Toolbar ]
  [ Text Editor ]  <- здесь пишем код
  [ Console ]      <- сюда выводятся сообщения
ПОЯСНЕНИЕ
Где хранится скетч. При первом сохранении Processing создаёт папку с именем скетча и кладёт в неё файл с тем же именем и расширением .pde, например MySketch/MySketch.pde. Имя файла и папки должны совпадать — иначе Processing предложит переложить файл. Картинки, шрифты и другие ресурсы кладут во вложенную папку data/. Эта структура понадобится и в Части II, где тот же скетч собирается под Android.

Среда разработки Processing минималистична: кнопки «Запустить» и «Стоп», редактор кода и консоль.

Структура скетча

Скетч (программа на Processing) состоит минимум из двух функций:

• setup() — вызывается один раз при старте (настройки).

• draw() — вызывается в бесконечном цикле (рисование и анимация).

ИТОГИ
Итоги главы 2

• В среде три главные зоны: панель с Run/Stop, редактор кода и консоль для сообщений и ошибок.
• Любой скетч строится вокруг двух функций: setup() — один раз при старте, draw() — каждый кадр.
• Скетч хранится в папке с тем же именем, ресурсы — во вложенной папке data/.

Глава 3 · Основы Processing

Основы синтаксиса

Здесь начинается основа всей книги. Сначала разберём две главные функции Processing, затем научимся рисовать простые фигуры. Важно понять не отдельные команды, а порядок работы программы: сначала настройка, потом постоянное обновление кадра.

3.1 Функция setup()

Функция setup() вызывается один раз при запуске программы. Здесь устанавливаются начальные параметры.

void setup() {
  size(800, 600);    // Установка размера окна
  background(255);   // Установка белого фона
}
ПОЯСНЕНИЕ
Разбор. setup() выполняется один раз сверху вниз. size() создаёт окно, затем background() закрашивает его. Если здесь загрузить изображение или создать объект, это тоже произойдёт только при старте.

Команда size(width, height) задает размер окна. Если её не вызвать, окно будет размером 100×100.

3.2 Функция draw()

Функция draw() вызывается в цикле примерно 60 раз в секунду. Именно здесь происходит всё рисование и обновление экрана.

void draw() {
  background(255);                         // Очистка фона
  fill(0);                                 // Установка чёрного цвета заливки
  ellipse(mouseX, mouseY, 50, 50);         // Рисование круга в позиции мыши
}
ПОЯСНЕНИЕ
Что здесь происходит. draw() повторяется снова и снова. Сначала фон очищается, затем выбирается цвет и рисуется круг в текущих координатах мыши. Поэтому круг визуально следует за курсором.

Если не вызывать background() внутри draw(), предыдущие рисунки останутся на экране — это можно использовать для создания «следов».

ЗАМЕТКА
Попробуй изменить. Перенеси background(255) из draw() в setup(). Окно очистится только один раз, и круг начнёт оставлять след. Так проще всего почувствовать разницу между setup() и draw().

Processing предоставляет простые команды для рисования форм:

rect(x, y, w, h)Прямоугольник с верхним левым углом в (x, y)
ellipse(x, y, w, h)Эллипс с центром в (x, y)

Пример рисования

void setup() {
  size(400, 400);
}
void draw() {
  background(255);
  fill(150, 0, 0);
  rect(50, 50, 100, 100);          // Красный квадрат
  fill(0, 150, 0);
  ellipse(200, 200, 100, 100);     // Зелёный круг
  fill(0, 0, 150);
  triangle(300, 50, 350, 150, 250, 150);  // Синий треугольник
}

3.4 Настройка обводки

Для управления обводкой фигур используются команды:

• stroke(r, g, b) — цвет линии/обводки.

• strokeWeight(толщина) — толщина линии.

• noStroke() — отключить обводку.

void draw() {
  stroke(255, 0, 0);    // Красная обводка
  strokeWeight(5);      // Толщина 5 пикселей
  fill(200);
  rect(50, 50, 100, 100);
}
ЗАМЕТКА
Мини-проверка. Перед следующей главой ты должен уметь объяснить разницу между setup() и draw(), нарисовать базовые фигуры и понимать, зачем background() часто находится внутри draw().
ИТОГИ
Итоги главы 3
• setup() выполняется один раз и задаёт окно через size(); draw() повторяется примерно 60 раз в секунду.
• Базовые фигуры: line(), rect(), ellipse(), triangle(), point(), quad(), arc().
• fill() задаёт заливку, stroke() и strokeWeight() — обводку, noStroke() отключает её.
• background() внутри draw() очищает кадр; без него остаются «следы».
УПРАЖНЕНИЯ
Упражнения к главе 3
1. Практика. Нарисуйте домик: квадрат (стены), треугольник (крыша), прямоугольник (дверь) и два маленьких квадрата (окна).
2. Практика. Нарисуйте светофор: три круга (красный, жёлтый, зелёный) друг под другом в прямоугольнике.
3. Практика. Используя line(), нарисуйте звезду (пятиконечную) в центре экрана.

Переменные и типы данных

Переменная — это имя, под которым программа хранит значение. Например, координату круга, скорость, цвет или текст. Если представить код как модель происходящего на экране, то переменные хранят состояние этой модели и меняются вместе с ней.

4.1 Типы данных

В Processing используются привычные типы данных Java. Для начала достаточно следующих:

ТипОписаниеПример
intЦелое числоint x = 10;
floatЧисло с плавающей точкойfloat pi = 3.14;
booleanЛогическое значение (true/false)boolean flag = true;
charОдин символchar letter = 'A';
StringСтрока текстаString name = "Processing";
colorЦветcolor c = color(255, 0, 0);

4.2 Объявление и инициализация

void setup() {
  int x = 100;               // Объявление + инициализация
  float y;                   // Только объявление
  y = 200.5;                 // Инициализация позже
  String greeting = "Привет!";
  println(greeting + " x = " + x);
}

4.3 Встроенные системные переменные

Processing предоставляет готовые переменные:

• width, height — ширина и высота окна.

• mouseX, mouseY — текущие координаты мыши.

• pmouseX, pmouseY — предыдущие координаты мыши.

• frameCount — количество прошедших кадров.

• frameRate — частота кадров (кадров/сек).

4.4 Область видимости (scope)

Переменные, объявленные вне функций, видны во всём скетче (глобальные). Переменные внутри функции видны только в ней.

int globalX = 200;  // Глобальная переменная
void setup() {
  int localY = 50;  // Локальная переменная
  println(globalX); // Доступна
  println(localY);  // Доступна
}
void draw() {
  println(globalX); // Доступна
  println(localY);  // Ошибка! localY не видна здесь
}
ВНИМАНИЕ
Частая ошибка. Локальная переменная существует только внутри блока, где она создана. localY появилась в setup(), поэтому draw() о ней ничего не знает. Если значение нужно в нескольких функциях, объявляй переменную снаружи функций.

4.5 Математические операции

int a = 10 + 5;    // Сложение
int b = 10 - 5;    // Вычитание
int c = 10 * 5;    // Умножение
int d = 10 / 5;    // Деление (целочисленное для int)
float e = 10.0 / 3.0; // Деление (вещественное)
int f = 10 % 3;    // Остаток от деления (1)
ВНИМАНИЕ
Важно. Тип влияет на результат операции. Для int выражение 10 / 3 даст 3, потому что дробная часть отбрасывается. Если нужен результат 3.333..., хотя бы одно число должно быть float, например 10.0 / 3.

Полезные встроенные функции:

• map(value, fromLow, fromHigh, toLow, toHigh) — переводит число из одного диапазона в другой.

• constrain(value, min, max) — ограничивает значение диапазоном.

• dist(x1, y1, x2, y2) — расстояние между двумя точками.

• lerp(a, b, t) — линейная интерполяция.

ИТОГИ
Итоги главы 4
• Переменная хранит состояние программы: координаты, скорость, цвет, текст.
• Основные типы: int, float, boolean, char, String и color.
• Глобальные переменные видны во всём скетче, локальные — только внутри своего блока.
• Тип влияет на результат: 10 / 3 для int даёт 3, для float — 3.333…
• map(), constrain(), dist() и lerp() избавляют от ручных вычислений.
УПРАЖНЕНИЯ
Упражнения к главе 4
1. Практика. Объявите переменные для x и y круга. Заставьте круг двигаться по диагонали, увеличивая x и y на 1 каждый кадр.
2. Практика. Используя map(), сделайте так, чтобы круг следовал за мышью по X, но с отображением диапазона 0–width в диапазон 0–255 (цвет).
3. Практика. Нарисуйте две точки и выведите на экран расстояние между ними, используя dist().

Условные операторы

Условие позволяет программе выбирать, что делать дальше. Логика простая: проверяем выражение, получаем true или false и выполняем нужную ветку. Именно на условиях строятся кнопки, столкновения, ограничения движения и почти любая реакция интерфейса.

5.1 if, else if, else

void draw() {
  background(255);
  if (mouseX < width / 3) {
    fill(255, 0, 0);        // Красный, если мышь в левой трети
  } else if (mouseX < 2 * width / 3) {
    fill(0, 255, 0);        // Зелёный, если мышь в центре
  } else {
    fill(0, 0, 255);        // Синий, если мышь в правой трети
  }
  ellipse(mouseX, height / 2, 100, 100);
}
ПОЯСНЕНИЕ
Разбор. Цепочка if → else if → else проверяется сверху вниз. Как только найдено первое подходящее условие, остальные ветки уже не выполняются. Поэтому порядок условий иногда меняет результат программы.

5.2 Логические операторы

• && — логическое И (оба условия истинны)

• || — логическое ИЛИ (хотя бы одно истинно)

• ! — логическое НЕ (отрицание)

// Круг зелёный только если мышь в квадрате 200×200 в центре
if (mouseX > 100 && mouseX < 300 && mouseY > 100 && mouseY < 300) {
  fill(0, 255, 0);
} else {
  fill(255, 0, 0);
}
ellipse(width / 2, height / 2, 100, 100);
ПОЯСНЕНИЕ
Что здесь происходит. Условие можно прочитать буквально: X должен быть между 100 и 300 И Y тоже должен быть между 100 и 300. Только тогда курсор находится внутри квадрата.

Глава 6 · Основы Processing

Циклы

Цикл нужен, когда одно и то же действие повторяется много раз. Вместо десяти одинаковых строк можно написать одну и указать, сколько раз её выполнить. Главное здесь — понимать три вещи: с какого значения начинаем, пока какое условие работаем и как меняем счётчик.

6.1 for

Используется, когда известно количество повторений.

void draw() {
  background(255);
  // Рисуем 10 кругов по горизонтали
  for (int i = 0; i < 10; i++) {
    float x = map(i, 0, 9, 50, width - 50);
    ellipse(x, height / 2, 40, 40);
  }
}
ПОЯСНЕНИЕ
Разбор. У for три части: int i = 0 создаёт счётчик, i < 10 проверяет, можно ли выполнить ещё один проход, i++ увеличивает счётчик после прохода. В итоге тело цикла выполнится для i от 0 до 9.

6.2 while

Используется, когда количество повторений заранее неизвестно.

void draw() {
  background(255);
  int i = 0;
  while (i < 10) {
    float x = map(i, 0, 9, 50, width - 50);
    ellipse(x, height / 2, 40, 40);
    i++;
  }
}
ВНИМАНИЕ
Частая ошибка. В while нужно самому менять переменную, от которой зависит условие. Если убрать i++, i навсегда останется равным 0 и цикл не закончится.

6.3 Вложенные циклы

Вложенный цикл нужен, когда элементы расположены по двум измерениям, например по строкам и столбцам.

void draw() {
  background(255);
  for (int row = 0; row < 5; row++) {
    for (int col = 0; col < 8; col++) {
      float x = map(col, 0, 7, 40, width - 40);
      float y = map(row, 0, 4, 40, height - 40);
      fill(col * 30, row * 50, 150);
      rect(x, y, 30, 30);
    }
  }
}
ПОЯСНЕНИЕ
Что здесь происходит. Внешний цикл выбирает строку, внутренний проходит по столбцам. Для каждой пары row и col получается одна ячейка. Это базовый шаблон для сеток, таблиц, пиксельных эффектов и игровых полей.
ЗАМЕТКА
Мини-проверка. Проверь себя: можешь ли ты без запуска кода сказать, какие значения примет i в for-цикле и почему while может стать бесконечным?
ИТОГИ
Итоги главы 6
• for используют, когда число повторений известно заранее; while — когда нет.
• У for три части: начальное значение, условие продолжения и шаг.
• В while переменную условия нужно менять самому, иначе цикл станет бесконечным.
• Вложенные циклы — стандартный шаблон для сеток, таблиц и пиксельных эффектов.
УПРАЖНЕНИЯ

3. Практика. Нарисуйте 100 кругов со случайными координатами и размерами (используйте random() внутри цикла).

Функции

Функция — это отдельный кусок программы с понятной задачей. Она помогает не копировать один и тот же код, а вызвать его по имени и передать нужные параметры. Чем больше становится проект, тем важнее разбивать его на небольшие функции.

7.1 Создание своей функции

void setup() {
  size(400, 400);
}
void draw() {
  background(255);
  drawFlower(100, 100, 30);
  drawFlower(300, 200, 50);
  drawFlower(200, 300, 40);
}
// Своя функция: рисует цветок в позиции (x, y)
void drawFlower(float x, float y, float size) {
  fill(255, 255, 0);
  ellipse(x, y, size, size);           // Центр
  fill(255, 100, 100);
  for (int i = 0; i < 5; i++) {
    float angle = TWO_PI / 5 * i;
    float px = x + cos(angle) * size;
    float py = y + sin(angle) * size;
    ellipse(px, py, size * 0.6, size * 0.6);  // Лепестки
  }
}
ПОЯСНЕНИЕ
Разбор. drawFlower() не знает заранее, где будет цветок и какого он размера. Эти значения приходят через параметры x, y и size. Поэтому одной функцией можно нарисовать сколько угодно цветов в разных местах.

7.2 Функции с возвращаемым значением

Функция может не только выполнять действия, но и возвращать результат.

void draw() {
  background(255);
  float speed = calculateSpeed(mouseX, mouseY);
  ellipse(mouseX, mouseY, 20 + speed, 20 + speed);
}
float calculateSpeed(float x, float y) {
  float centerDist = dist(x, y, width / 2, height / 2);
  return map(centerDist, 0, width / 2, 1, 10);
}
ПОЯСНЕНИЕ
Что здесь происходит. calculateSpeed() сначала считает расстояние до центра, а затем return отдаёт готовое число обратно в draw(). Разница с void-функцией именно в этом: функция не только выполняет действия, но и возвращает результат.

7.3 Параметры по умолчанию (перегрузка функций)

В Java/Processing можно создавать несколько функций с одинаковым именем, но разными параметрами.

void setup() {
  setColor();          // Установит цвет по умолчанию
  setColor(255, 0, 0); // Установит красный
}
void setColor() {
  fill(128);
}
void setColor(int r, int g, int b) {
  fill(r, g, b);
}
ИТОГИ
Итоги главы 7
• Функция — именованный кусок кода с понятной задачей; параметры делают её универсальной.
• void-функция выполняет действия, функция с типом возвращает результат через return.
• Несколько функций с одним именем и разными параметрами — перегрузка.
• Разбиение кода на функции делает проект читаемым и избавляет от копирования.

Массивы

Массив нужен, когда значений одного типа становится много: координаты частиц, скорости шариков, результаты измерений. Вместо десятков переменных мы храним данные в одной структуре и обращаемся к элементам по индексу.

8.1 Создание и заполнение

int[] numbers = new int[5];          // Массив из 5 элементов
numbers[0] = 10;
numbers[1] = 20;
numbers[2] = 30;
numbers[3] = 40;
numbers[4] = 50;
// Короткая запись
int[] values = { 10, 20, 30, 40, 50 };
float[] randoms = new float[100];
for (int i = 0; i < randoms.length; i++) {
  randoms[i] = random(255);
}
ВНИМАНИЕ
Важно. Индексы массива начинаются с 0. Для массива длины 100 допустимы индексы 0...99. Поэтому условие i < randoms.length безопаснее, чем вручную писать i < 100.

8.2 Использование массива в анимации

Массивы идеально подходят для хранения множества объектов (частиц, точек, шариков).

float[] x = new float[50];
float[] y = new float[50];
float[] speeds = new float[50];
void setup() {
  size(600, 400);
  for (int i = 0; i < x.length; i++) {
    x[i] = random(width);
    y[i] = random(height);
    speeds[i] = random(1, 5);
  }
}
void draw() {
  background(255);
  for (int i = 0; i < x.length; i++) {
    y[i] += speeds[i];
    if (y[i] > height) y[i] = 0;
    ellipse(x[i], y[i], 10, 10);
  }
}
ПОЯСНЕНИЕ
Разбор. Здесь три массива связаны одним индексом. x[7], y[7] и speeds[7] описывают один и тот же объект. Это работает, но при большом проекте удобнее перейти к классу и хранить данные объекта вместе.

8.3 Двумерные массивы

int[][] grid = new int[8][8];
void setup() {
  size(400, 400);
  for (int i = 0; i < 8; i++) {
    for (int j = 0; j < 8; j++) {
      grid[i][j] = (i + j) % 2 == 0 ? 255 : 0;
    }
  }
}
void draw() {
  for (int i = 0; i < 8; i++) {
    for (int j = 0; j < 8; j++) {
      fill(grid[i][j]);
      rect(i * 50, j * 50, 50, 50);
    }
  }
}
ПОЯСНЕНИЕ
Разбор. Двумерный массив — это «массив массивов»: grid[i] — целый столбец, а grid[i][j] — одна клетка. Здесь i отвечает за номер столбца (x = i * 50), j — за номер строки (y = j * 50). Выражение (i + j) % 2 даёт 0 и 1 в шахматном порядке, поэтому клетки чередуются: 255 (белая) и 0 (чёрная).

8.4 ArrayList — динамический массив

Когда количество элементов заранее неизвестно, удобнее использовать ArrayList.

import java.util.ArrayList;
ArrayList<Float> values = new ArrayList<Float>();
void setup() {
  size(400, 200);
}
void draw() {
  values.add((float) mouseX);   // mouseX — int, приводим к float
  if (values.size() > 100) {
    values.remove(0);
  }
  background(255);
  for (int i = 0; i < values.size(); i++) {
    ellipse(values.get(i), height / 2, 5, 5);
  }
}
ПОЯСНЕНИЕ
Разбор. ArrayList сам меняет размер: add() добавляет элемент в конец, remove(0) удаляет самый старый, size() возвращает текущее количество, get(i) — элемент по индексу. В угловых скобках указывается тип элементов, причём это должен быть класс-«обёртка»: Float вместо float, Integer вместо int. Поэтому mouseX (целое число) приводится к float перед добавлением. Строка import java.util.ArrayList в Processing необязательна — этот класс подключён по умолчанию.
ЗАМЕТКА
Мини-проверка. Проверь себя: индекс первого элемента равен 0, последний индекс равен length - 1, а выход за этот диапазон означает ошибку.
ИТОГИ
Итоги главы 8
• Массив хранит много значений одного типа; индексы начинаются с 0 и заканчиваются length - 1.
• Цикл for по length — основной способ обойти массив.
• Двумерный массив grid[i][j] удобен для сеток и игровых полей.
• ArrayList меняет размер сам: add(), remove(), size(), get().
УПРАЖНЕНИЯ
Упражнения к главе 8
1. Практика. Создайте массив из 20 «снежинок» (кружков), которые падают сверху вниз с разными скоростями. Когда снежинка достигает низа, она появляется наверху.

Система координат и трансформации

Трансформации позволяют перестать вручную пересчитывать каждую координату. Мы временно двигаем, поворачиваем или масштабируем саму систему координат, рисуем объект в ней, а затем возвращаемся обратно. Это особенно удобно для сложных составных объектов и анимации.

9.1 Система координат

В Processing начало координат (0, 0) находится в верхнем левом углу. Ось X направлена вправо, ось Y — вниз.

(0,0) ──────────► X
  │
  │
  ▼
  Y

9.2 pushMatrix() и popMatrix()

Эти команды сохраняют и восстанавливают текущую систему координат. Они позволяют временно перемещать, вращать и масштабировать отдельные объекты, не влияя на остальной рисунок.

9.3 translate(), rotate(), scale()

void draw() {
  background(255);
  // Рисуем квадрат без трансформации
  fill(200);
  rect(0, 0, 50, 50);
  pushMatrix();
  translate(100, 100);     // Сдвигаем начало координат
  rotate(radians(45));     // Поворачиваем на 45 градусов
  scale(1.5);              // Увеличиваем в 1.5 раза
  fill(255, 0, 0);
  rect(0, 0, 50, 50);      // Рисуем в новой системе координат
  popMatrix();
  // Этот квадрат не зависит от трансформаций выше
  fill(0, 255, 0);
  rect(100, 200, 50, 50);
}
ПОЯСНЕНИЕ
Разбор. pushMatrix() сохраняет текущую систему координат, затем translate/rotate/scale временно её меняют. popMatrix() возвращает всё обратно. Без этой пары трансформации начали бы влиять и на следующие объекты.

9.4 Анимация вращения

float angle = 0;
void draw() {
  background(255);
  pushMatrix();
  translate(width / 2, height / 2);
  rotate(angle);
  rectMode(CENTER);
  fill(100, 150, 255);
  rect(0, 0, 100, 100);
  popMatrix();
  angle += 0.02;
}
ЗАМЕТКА
Попробуй изменить. Поставь 0.005 вместо 0.02 и квадрат будет вращаться медленнее. Поставь отрицательное значение, например -0.02, и направление вращения поменяется.
ИТОГИ
Итоги главы 9
• Начало координат — левый верхний угол, ось Y направлена вниз.
• translate(), rotate() и scale() меняют саму систему координат, а не объект.
• pushMatrix() и popMatrix() ограничивают действие трансформаций.
• Углы в rotate() задаются в радианах; radians() переводит градусы.

Случайные числа

Случайность полезна, когда объектам нужны разные позиции, размеры или поведение. В Processing есть обычные случайные значения и более плавный шум. Первый вариант хорошо подходит для резких случайных изменений, второй — для естественного движения.

10.1 random()

Функция random() возвращает случайное число.

float r = random(100);          // Случайное число от 0 до 100
float r2 = random(50, 100);     // Случайное число от 50 до 100
int r3 = (int) random(10);      // Случайное целое от 0 до 9

10.2 Пример: случайные круги

void setup() {
  size(600, 400);
  background(255);
  noLoop();  // Остановить draw() после первого кадра
}
void draw() {
  for (int i = 0; i < 100; i++) {
    float x = random(width);
    float y = random(height);
    float r = random(10, 50);
    fill(random(255), random(255), random(255), random(100, 200));
    noStroke();
    ellipse(x, y, r, r);
  }
}
ПОЯСНЕНИЕ
Что здесь происходит. random() вызывается отдельно для координат, размера и цвета, поэтому каждый круг получается независимым. noLoop() здесь важен: без него draw() запускался бы снова и вся случайная картинка постоянно менялась.

10.3 Функция noise()

Для более естественных, плавных случайных значений используется шум Перлина:

void setup() {
  size(400, 400);
}
void draw() {
  float n = noise(frameCount * 0.01);  // Плавное случайное значение от 0 до 1
  float x = map(n, 0, 1, 0, width);
  ellipse(x, height / 2, 20, 20);
}
ПОЯСНЕНИЕ
Разбор. noise() тоже даёт меняющееся значение, но соседние значения похожи друг на друга. Поэтому движение получается плавным. Чем меньше шаг frameCount * 0.01, тем медленнее и мягче меняется результат.
ИТОГИ
Итоги главы 10
• random(max) и random(min, max) дают независимые случайные числа; (int) отбрасывает дробную часть.
• noLoop() останавливает draw() — удобно для статичных случайных картинок.
• noise() — шум Перлина: соседние значения похожи, поэтому движение получается плавным.
• Чем меньше шаг аргумента noise(), тем медленнее меняется значение.
УПРАЖНЕНИЯ
Упражнения к главе 10
1. Практика. Создайте программу, которая в случайных местах экрана рисует разноцветные круги случайного размера. При нажатии на пробел экран очищается.
2. Практика. Используя шум Перлина noise(), создайте плавно движущуюся точку, которая имитирует полёт мухи.
Глава 11 · Основы Processing

Анимация и время

Анимация в Processing — это не отдельный режим. Мы просто много раз перерисовываем кадр и немного меняем значения между кадрами. Для управления временем можно считать кадры или работать с миллисекундами с момента запуска.

11.1 frameCount

Счётчик кадров — увеличивается на 1 каждый вызов draw().

void draw() {
  background(255);
  float x = (frameCount * 2) % width;  // Движение слева направо
  ellipse(x, height / 2, 30, 30);
}
ПОЯСНЕНИЕ
Разбор. frameCount растёт на 1 каждый кадр. Умножение на 2 задаёт скорость по X, а оператор % width возвращает координату к началу, когда она выходит за ширину окна.

11.2 millis()

Возвращает количество миллисекунд, прошедших с запуска.

void draw() {
  background(255);
  float t = millis() / 1000.0;  // Время в секундах
  float x = map(sin(t), -1, 1, 50, width - 50);
  fill(255, 0, 0);
  ellipse(x, height / 2, 40, 40);
  fill(0);
  text("Время: " + nf(t, 0, 1) + " сек", 20, 30);
}
ВНИМАНИЕ
Важно. millis() измеряет реальное время с запуска, а frameCount считает кадры. Если частота кадров просела, frameCount будет идти медленнее, но millis() продолжит показывать прошедшее время.

11.3 Sin и Cos для плавных движений

float angle = 0;
void draw() {
  background(255);
  // Плавное движение по кругу
  float x = width / 2 + cos(angle) * 150;
  float y = height / 2 + sin(angle) * 150;
  fill(100, 150, 255);
  ellipse(x, y, 40, 40);
  angle += 0.02;
}
ИТОГИ
Итоги главы 11
• Анимация — это перерисовка кадра с небольшим изменением переменных.
• frameCount считает кадры, millis() — реальное время в миллисекундах.
• Для движения, не зависящего от частоты кадров, опирайтесь на millis().
• sin() и cos() дают плавные колебания и движение по кругу.

Глава 12 · Основы Processing

Работа с цветом

Цвет в Processing — это тоже данные. Его можно задавать числами, менять прозрачность, хранить в переменной и плавно смешивать. Это удобно не только для оформления, но и для визуализации состояний: например, температуры, расстояния или уровня сигнала.

12.1 Цветовые модели

Processing поддерживает несколько цветовых моделей. По умолчанию используется RGB (Red, Green, Blue) со значениями от 0 до 255.

fill(255, 0, 0);       // Красный (R=255, G=0, B=0)
fill(0, 255, 0);       // Зелёный
fill(0, 0, 255);       // Синий
fill(255, 255, 0);     // Жёлтый
fill(128, 128, 128);   // Серый

12.2 Прозрачность (альфа-канал)

Четвёртый параметр задаёт прозрачность (0 — полностью прозрачный, 255 — полностью непрозрачный):

fill(255, 0, 0, 100);   // Полупрозрачный красный
fill(0, 0, 255, 50);    // Очень прозрачный синий

12.3 colorMode()

Можно переключиться в режим HSB (Hue, Saturation, Brightness):

void setup() {
  size(400, 400);
  colorMode(HSB, 360, 100, 100);  // H: 0-360, S: 0-100, B: 0-100
}
void draw() {
  background(200);
  for (int i = 0; i < 360; i += 10) {
    fill(i, 80, 100);
    rect(i * (width / 360.0), 0, width / 36.0, height);
  }
}
ПОЯСНЕНИЕ
Зачем HSB. В RGB трудно «пройтись по радуге»: при переходе от красного к синему меняются сразу три числа. В HSB за оттенок отвечает одно число H (0–360 по цветовому кругу), а насыщенность S и яркость B остаются постоянными. Поэтому цикл по i от 0 до 360 рисует плавный спектр. colorMode() действует до следующего вызова, так что все последующие fill() и stroke() тоже понимают значения как HSB.

12.4 lerpColor()

Плавный переход между двумя цветами:

color c1 = color(255, 0, 0);
color c2 = color(0, 0, 255);
void draw() {
  float t = map(mouseX, 0, width, 0, 1);
  color current = lerpColor(c1, c2, t);
  background(current);
  fill(0);
  text("Смешение: " + nf(t, 0, 2), 20, 30);
}
ПОЯСНЕНИЕ
Разбор. lerpColor() смешивает два цвета по параметру t. При t = 0 получаем первый цвет, при t = 1 второй, а значения между ними дают плавный переход.
ИТОГИ
Итоги главы 12
• По умолчанию цвет задаётся в RGB от 0 до 255; четвёртый параметр — прозрачность.
• colorMode(HSB) удобен, когда нужно менять оттенок одним числом.
• Цвет можно хранить в переменной типа color.
• lerpColor() плавно смешивает два цвета по параметру от 0 до 1.

Упражнения к главе 12

13.1 Мышь

Processing предоставляет несколько встроенных функций и переменных для работы с мышью.

void setup() {
  size(400, 400);
}
void draw() {
  background(255);
  ellipse(mouseX, mouseY, 30, 30);
}
void mousePressed() {
  println("Мышь нажата в (" + mouseX + ", " + mouseY + ")");
}
void mouseReleased() {
  println("Мышь отпущена");
}
void mouseClicked() {
  println("Клик!");
}
void mouseDragged() {
  println("Перетаскивание...");
}
void mouseMoved() {
  println("Движение мыши");
}
void mouseWheel(MouseEvent event) {
  float delta = event.getCount();
  println("Колесико: " + delta);

ПОЯСНЕНИЕ
Что здесь происходит. draw() опрашивается постоянно, а mousePressed(), mouseReleased() и другие обработчики вызываются только в момент события. Поэтому в обработчиках удобно менять состояние, а в draw() уже рисовать экран по этому состоянию.

13.2 Клавиатура

void setup() {
  size(400, 400);
}
void draw() {
  // Рисование зависит от нажатой клавиши
  if (keyPressed) {
    fill(255, 0, 0);
    text("Нажата: " + key, 20, 30);
  }
}
void keyPressed() {
  println("Клавиша нажата: " + key + " (код: " + keyCode + ")");
  if (key == 'r') {
    background(255, 0, 0);
  } else if (key == 'g') {
    background(0, 255, 0);
  } else if (key == 'b') {
    background(0, 0, 255);
  } else if (keyCode == UP) {
    println("Стрелка вверх!");
  }
}
void keyReleased() {
  println("Клавиша отпущена");
}
ПОЯСНЕНИЕ
key или keyCode. key содержит символ нажатой клавиши ('r', '1', ' '). Для специальных клавиш — стрелок, Shift, Ctrl — символа нет: тогда key равен CODED, а конкретная клавиша лежит в keyCode (UP, DOWN, LEFT, RIGHT, SHIFT…). Переменная keyPressed (без скобок) истинна, пока клавиша удерживается, а функция keyPressed() вызывается один раз в момент нажатия.

13.3 Практический пример: клавиатурный Paint

float brushSize = 10;
color brushColor = color(0);
void setup() {
  size(600, 400);
  background(255);
}
void draw() {
  if (mousePressed) {
    stroke(brushColor);
    strokeWeight(brushSize);
    line(mouseX, mouseY, pmouseX, pmouseY);
  }
}
void keyPressed() {
  if (key == '1') brushColor = color(255, 0, 0);
  if (key == '2') brushColor = color(0, 255, 0);
  if (key == '3') brushColor = color(0, 0, 255);
  if (key == '+') brushSize += 2;
  if (key == '-') brushSize = max(1, brushSize - 2);
  if (key == ' ') background(255);  // Очистка
}
ПОЯСНЕНИЕ
Разбор. Paint хранит два состояния: текущий цвет и размер кисти. Нажатие клавиши меняет эти переменные, а draw() использует их при следующем движении мыши. Интерфейс и рисование связаны через состояние.
ИТОГИ
Итоги главы 13
• mouseX, mouseY, pmouseX, pmouseY и mousePressed описывают состояние мыши в каждом кадре.
• Функции-события mousePressed(), mouseReleased(), mouseDragged(), mouseWheel() вызываются один раз в момент события.
• key хранит символ, keyCode — специальную клавишу, когда key == CODED.
• Обработчики меняют переменные состояния, а рисует draw().

Глава 14 · Основы Processing

Текст и шрифты

Текст нужен почти в любом интерфейсе: подписи, значения датчиков, подсказки, кнопки и сообщения об ошибках. Здесь важно не только вывести строку, но и правильно задать размер, выравнивание и область, в которую она должна помещаться.

14.1 Вывод текста: text()

Базовый вывод текста осуществляется функцией text():

void setup() {
  size(400, 200);
  background(255);
}
void draw() {
  background(255);
  fill(0);
  text("Привет, Processing!", 20, 100);
}

Функция text() принимает строку и координаты (x, y), где y — это базовая линия (baseline) текста.

ВНИМАНИЕ
Важно. Координата y у text() по умолчанию указывает не на верх строки, а на базовую линию символов. Поэтому текст иногда визуально оказывается выше или ниже, чем ожидается. Для интерфейсов проще задавать textAlign() и считать позицию от центра элемента.

14.2 Размер и настройки текста

• textSize(size) — задаёт размер шрифта в пикселях.

• textLeading(value) — межстрочный интервал.

• textMode(MODEL) или textMode(SHAPE) — режим отрисовки.

void draw() {
  background(255);
  textSize(16);
  text("Маленький текст", 20, 50);
  textSize(32);
  text("Средний текст", 20, 100);
  textSize(48);
  fill(100, 100, 255);
  text("Крупный текст", 20, 160);
}

14.3 Выравнивание текста: textAlign()

void draw() {
  background(255);
  stroke(200);
  line(width / 2, 0, width / 2, height);
  textSize(20);
  textAlign(LEFT);
  text("LEFT", width / 2, 40);
  textAlign(CENTER);
  text("CENTER", width / 2, 80);
  textAlign(RIGHT);
  text("RIGHT", width / 2, 120);
  textAlign(CENTER, TOP);
  text("TOP", width / 2, 160);
  textAlign(CENTER, CENTER);
  text("CENTER", width / 2, 200);
  textAlign(CENTER, BOTTOM);
  text("BOTTOM", width / 2, 240);
}

14.4 Ширина и высота текста

• textWidth(string) — возвращает ширину строки в пикселях.

• textAscent() — высота символов над baseline.

• textDescent() — высота символов под baseline.

void draw() {
  background(255);
  textSize(24);
  String msg = "Processing";
  float tw = textWidth(msg);
  fill(200, 200, 255);
  rect(20, 50, tw, textAscent() + textDescent());
  fill(0);
  text(msg, 20, 50 + textAscent());
  fill(255, 200, 200);
  float boxX = 200, boxY = 150, boxW = 150, boxH = 40;
  rect(boxX, boxY, boxW, boxH);
  fill(0);
  textAlign(CENTER, CENTER);
  textSize(16);
  text("Центр", boxX + boxW / 2, boxY + boxH / 2);
}
ПОЯСНЕНИЕ
Разбор. textWidth() полезен, когда размер блока зависит от текста. Сначала измеряем строку, затем рисуем фон нужной ширины и только после этого выводим сам текст.

14.5 Работа со шрифтами

15.3 Создание кнопок (без библиотек)

boolean button1Pressed = false;
boolean button2Pressed = false;
void setup() {
  size(400, 300);
  surface.setTitle("Кнопки");
}
void draw() {
  background(240);
  drawButton(50, 100, 120, 50, "Кнопка 1", button1Pressed);
  drawButton(230, 100, 120, 50, "Кнопка 2", button2Pressed);
  fill(0);
  textSize(16);
  text("Кнопка 1: " + (button1Pressed ? "ВКЛ" : "ВЫКЛ"), 50, 240);
  text("Кнопка 2: " + (button2Pressed ? "ВКЛ" : "ВЫКЛ"), 50, 270);
}
void drawButton(int x, int y, int w, int h, String label, boolean pressed) {
  if (pressed) {
    fill(150, 200, 255);
    stroke(100, 150, 200);
  } else {
    fill(220);
    stroke(180);
  }
  strokeWeight(2);
  rect(x, y, w, h, 5);
  fill(pressed ? 0 : 50);
  textAlign(CENTER, CENTER);
  textSize(16);
  text(label, x + w / 2, y + h / 2);
}
void mousePressed() {
  if (isInside(mouseX, mouseY, 50, 100, 120, 50)) {
    button1Pressed = !button1Pressed;
  }
  if (isInside(mouseX, mouseY, 230, 100, 120, 50)) {
    button2Pressed = !button2Pressed;
  }
}
boolean isInside(int mx, int my, int x, int y, int w, int h) {
  return mx > x && mx < x + w && my > y && my < y + h;
}
ПОЯСНЕНИЕ
Разбор. Кнопка здесь не является специальным объектом. Мы просто проверяем, попала ли точка мыши внутрь прямоугольника. Если попала, меняем boolean-переменную. Это и есть минимальная логика клика по кнопке.

15.4 Создание слайдера (без библиотек)

int sliderX = 300;
int sliderMin = 50, sliderMax = 350;
boolean dragging = false;
void setup() {
  size(400, 200);
  surface.setTitle("Слайдер");
}
void draw() {
  background(240);
  fill(200);
  rect(50, 80, 300, 10, 5);
  fill(100, 150, 255);
  ellipse(sliderX, 85, 20, 20);
  float val = map(sliderX, sliderMin, sliderMax, 0, 100);
  fill(0);
  textAlign(CENTER, CENTER);
  textSize(20);
  text(nf(val, 0, 1) + "%", width / 2, 150);
}
void mousePressed() {
  if (dist(mouseX, mouseY, sliderX, 85) < 15) {
    dragging = true;
  }
}
void mouseDragged() {
  if (dragging) {
    sliderX = constrain(mouseX, sliderMin, sliderMax);
  }
}
void mouseReleased() {
  dragging = false;
}
ПОЯСНЕНИЕ
Что здесь происходит. constrain() не даёт бегунку выйти за края, а map() переводит его координату в удобное значение 0...100. Это типичный шаблон: координата интерфейса и реальное значение хранятся в разных диапазонах.

15.5 Чекбоксы

Классы и объекты (ООП)

ООП становится полезным, когда в программе много похожих сущностей. Вместо отдельных наборов x, y, speed и color можно описать один класс и создавать из него объекты. Так данные объекта и функции для работы с ними находятся рядом.

16.1 Что такое класс?

Класс — это шаблон (чертёж), описывающий состояние (поля) и поведение (методы) объектов.

Объект — конкретный экземпляр класса.

16.2 Создание класса

class Ball {
  float x, y;     // Поля (данные)
  float vx, vy;
  float r;
  // Конструктор — вызывается при создании объекта
  Ball(float x, float y) {
    this.x = x;
    this.y = y;
    this.r = 20;
    this.vx = random(-2, 2);
    this.vy = random(-2, 2);
  }
  // Методы (поведение)
  void update() {
    x += vx;
    y += vy;
    if (x < 0 || x > width) vx *= -1;
    if (y < 0 || y > height) vy *= -1;
  }
  void display() {
    fill(100, 150, 255, 150);
    noStroke();
    ellipse(x, y, r * 2, r * 2);
  }
}
ПОЯСНЕНИЕ
Разбор. Поля x, y, vx, vy и r принадлежат конкретному объекту Ball. Конструктор получает стартовые координаты и заполняет начальное состояние. this.x означает «поле x этого объекта» и помогает отличать его от параметра x.

16.3 Создание объектов

Объекты создаются через new:

Ball b1;                     // Объявление переменной (вне функций)
Ball b2;
// Создание объектов — внутри setup():
b1 = new Ball(100, 200);
b2 = new Ball(300, 150);

16.4 Использование объектов

Ball b1, b2;
void setup() {
  size(400, 300);
  b1 = new Ball(100, 200);   // объекты создаём после size(),
  b2 = new Ball(300, 150);   // когда width и height уже известны
}
void draw() {
  background(255);
  b1.update();
  b1.display();
  b2.update();
  b2.display();
}
ВНИМАНИЕ
Важно. Переменную-объект можно объявить вне функций, но создавать сам объект через new лучше внутри setup(): до вызова size() переменные width и height ещё не имеют правильных значений. Если забыть создать объект, при первом вызове b1.update() программа остановится с ошибкой NullPointerException.

16.5 Массив объектов

Ball[] balls = new Ball[10];
void setup() {
  size(400, 300);
  for (int i = 0; i < balls.length; i++) {
    balls[i] = new Ball(random(width), random(height));
  }
}
void draw() {
  background(255);
  for (Ball b : balls) {
    b.update();
    b.display();
  }
}
ПОЯСНЕНИЕ
Что здесь происходит. Цикл for-each по очереди берёт каждый объект из массива balls. Для каждого шара сначала обновляется состояние, затем он рисуется. Такой порядок update() → display() удобно сохранять и в более сложных проектах.

16.6 Пример: вращающиеся квадраты

class RotatingBox {
  float x, y, size, angle, speed;
  RotatingBox(float x, float y, float size) {
    this.x = x;
    this.y = y;
    this.size = size;
    this.angle = random(TWO_PI);
    this.speed = random(0.01, 0.05);
  }
  void update() {
    angle += speed;
  }
  void display() {
    pushMatrix();
    translate(x, y);
    rotate(angle);
    fill(map(speed, 0.01, 0.05, 100, 255), 100, 200);
    rectMode(CENTER);
    rect(0, 0, size, size);
    popMatrix();
  }
}
RotatingBox[] boxes = new RotatingBox[20];
void setup() {
  size(600, 400);
  for (int i = 0; i < boxes.length; i++) {
    boxes[i] = new RotatingBox(
      random(width), random(height), random(20, 60)
    );
  }
}
void draw() {
  background(30);
  for (RotatingBox box : boxes) {
    box.update();
    box.display();
  }
}

Векторы и PVector

PVector упрощает работу с координатами, скоростью, ускорением и направлением. Вместо отдельных x и y мы работаем с одним объектом-вектором и применяем к нему готовые операции. Для анимации и простой физики это заметно упрощает код.

17.1 Что такое вектор?

Вектор — это направленный отрезок, имеющий длину (magnitude) и направление (heading). В двумерном пространстве вектор задаётся двумя компонентами: x и y.

17.2 Создание PVector

PVector v1 = new PVector(3, 4);          // Вектор (3, 4)
PVector v2 = new PVector(mouseX, mouseY); // Вектор от начала координат до мыши
PVector v3 = PVector.random2D();          // Случайное направление, длина 1

17.3 Базовые операции

PVector a = new PVector(10, 20);
PVector b = new PVector(30, 40);
PVector sum = PVector.add(a, b);       // Сложение: (40, 60)
PVector diff = PVector.sub(a, b);      // Вычитание: (-20, -20)
PVector scaled = PVector.mult(a, 2);   // Умножение на скаляр: (20, 40)
float len = a.mag();                   // Длина вектора: sqrt(10² + 20²)
a.setMag(50);                          // Установить длину в 50
a.normalize();                         // Привести к единичной длине
float d = PVector.dist(a, b);          // Расстояние между a и b (статический метод)
float d2 = a.dist(b);                  // Или экземплярный метод

17.4 Движение с ускорением

Классическая схема движения: позиция + скорость + ускорение

PVector position;
PVector velocity;
PVector acceleration;
void setup() {
  size(400, 300);
  position = new PVector(width / 2, height / 2);
  velocity = new PVector(0, 0);
}
void draw() {
  background(255);
  // Ускорение направлено к мыши
  PVector mouse = new PVector(mouseX, mouseY);
  PVector direction = PVector.sub(mouse, position);
  direction.setMag(0.1);
  acceleration = direction;
  velocity.add(acceleration);
  velocity.limit(5);        // Ограничение максимальной скорости
  position.add(velocity);
  fill(100, 150, 255);
  ellipse(position.x, position.y, 30, 30);
  // Вектор скорости
  stroke(255, 0, 0);
  line(position.x, position.y,
       position.x + velocity.x * 10,
       position.y + velocity.y * 10);
}
ПОЯСНЕНИЕ
Разбор. Схема движения читается сверху вниз: acceleration меняет velocity, затем velocity меняет position. Если перепутать порядок или каждый кадр заново обнулять velocity, движение будет вести себя совсем иначе.

17.5 Отталкивание от мыши

PVector pos;
PVector vel;
void setup() {
  size(400, 300);
  pos = new PVector(width / 2, height / 2);
  vel = new PVector(1, 2);
}
void draw() {
  background(255);
  // Сила отталкивания от мыши
  PVector mouse = new PVector(mouseX, mouseY);
  PVector repel = PVector.sub(pos, mouse);
  float dist = repel.mag();
  if (dist < 100) {
    repel.setMag(map(dist, 0, 100, 0.5, 0));
    vel.add(repel);
  }
  vel.limit(4);
  pos.add(vel);
  // Границы
  if (pos.x < 0 || pos.x > width) vel.x *= -1;
  if (pos.y < 0 || pos.y > height) vel.y *= -1;
  fill(200, 100, 100);
  ellipse(pos.x, pos.y, 30, 30);
}
ПОЯСНЕНИЕ
Что здесь происходит. PVector.sub(pos, mouse) строит направление от мыши к объекту. Затем длину этого вектора можно изменить и использовать как силу отталкивания. Поэтому PVector удобен: направление и величина хранятся в одном объекте.

17.6 PVector.fromAngle()

PVector direction;
float angle = 0;
void setup() {
  size(400, 300);
  direction = PVector.fromAngle(0);
}
void draw() {
  background(255);
  direction = PVector.fromAngle(angle);
  direction.mult(100);
  PVector center = new PVector(width / 2, height / 2);
  PVector tip = PVector.add(center, direction);
  stroke(0);
  line(center.x, center.y, tip.x, tip.y);
  fill(255, 0, 0);
  ellipse(tip.x, tip.y, 10, 10);
  angle += 0.02;
}
ПОЯСНЕНИЕ
Разбор. PVector.fromAngle(angle) создаёт вектор длиной 1, направленный под углом angle (в радианах, 0 — вправо, рост угла — по часовой стрелке, потому что ось Y направлена вниз). mult(100) растягивает его до 100 пикселей. Сложение с центром даёт координаты конца стрелки — так удобно рисовать стрелки часов, прицелы и лучи радара.

17.7 Полезные методы PVector

PVector v = new PVector(3, 4);
float m = v.mag();            // Длина: 5.0
float h = v.heading();        // Угол в радианах
v.rotate(0.1);                // Поворот вектора
v.limit(10);                  // Ограничить длину
v.setMag(1);                  // Установить длину = 1
PVector r = PVector.random2D();  // Случайный единичный вектор
float dp = a.dot(b);             // Скалярное произведение
ИТОГИ
Итоги главы 17
• PVector объединяет x и y в один объект и даёт готовые операции.
• add(), sub(), mult(), mag(), setMag(), normalize(), limit() и heading() — основные методы.
• Схема движения: ускорение меняет скорость, скорость меняет позицию.
• PVector.sub(a, b) задаёт направление от b к a, fromAngle() — вектор по углу.

Изображение в Processing можно воспринимать сразу на двух уровнях: как готовую картинку и как массив пикселей. Первый вариант нужен для обычного отображения, второй — когда требуется фильтр, эффект или собственная обработка.

18.4 Прямой доступ к пикселям через pixels[]

void setup() {
  size(200, 200);
}
void draw() {
  loadPixels();  // Загружаем пиксели окна в массив pixels[]
  for (int x = 0; x < width; x++) {
    for (int y = 0; y < height; y++) {
      int loc = x + y * width;
      float r = map(x, 0, width, 0, 255);
      float g = map(y, 0, height, 0, 255);
      float b = map(mouseX, 0, width, 0, 255);
      pixels[loc] = color(r, g, b);
    }
  }
  updatePixels();  // Применяем изменения
}
ПОЯСНЕНИЕ
Формула индекса. Экран хранится в pixels[] одной длинной строкой: сначала все пиксели первой строки, затем второй и так далее. Поэтому пиксель (x, y) лежит по индексу x + y * width. Пример: в окне шириной 200 пиксель (10, 2) имеет индекс 10 + 2 * 200 = 410. Перед чтением или записью обязательно вызвать loadPixels(), а после изменений — updatePixels(), иначе изменения не появятся на экране.

После эффекта режим нужно вернуть в BLEND, иначе он повлияет на всё, что рисуется дальше.

class Particle {
  float x, y;
  float size;
  Particle(float x, float y, float size) {
    this.x = x;
    this.y = y;
    this.size = size;
  }
  JSONObject toJSON() {
    JSONObject json = new JSONObject();
    json.setFloat("x", x);
    json.setFloat("y", y);
    json.setFloat("size", size);
    return json;
  }
}
void saveParticles(Particle[] particles, String filename) {
  JSONArray arr = new JSONArray();
  for (int i = 0; i < particles.length; i++) {
    arr.setJSONObject(i, particles[i].toJSON());
  }
  saveJSONArray(arr, filename);
}

Основы Processing + Arduino

Теперь Processing будет работать не только с экраном, но и с внешним устройством. Основная идея простая: Arduino отправляет или принимает данные через последовательный порт, а Processing читает эти строки и превращает их в графику, команды или элементы управления.

Повторение: Processing для главы 20

В примерах этой главы используются следующие концепции Processing. Если вы их забыли — краткий обзор ниже.

setup() и draw() — базовая структура любого скетча. setup() вызывается один раз, draw() — 60 раз в секунду.

import — подключение библиотек. Для Arduino нужна import processing.serial.*;.

size(w, h) — размер окна.

map(value, fromLow, fromHigh, toLow, toHigh) — переводит число из одного диапазона в другой. Например, map(analogValue, 0, 1023, 0, 255) превращает показания потенциометра 0–1023 в 0–255.

constrain(value, min, max) — ограничивает значение в диапазоне.

Массивы — float[] values = new float[100] хранит последние 100 значений с датчика.

fill(r, g, b) — цвет заливки. background(r, g, b) — цвет фона.

ellipse(x, y, w, h) — круг/овал. rect(x, y, w, h) — прямоугольник.

dist(x1, y1, x2, y2) — расстояние между двумя точками.

mouseX, mouseY — координаты мыши. mousePressed() — вызывается при нажатии.

text("текст", x, y) — вывод текста. textAlign(CENTER, CENTER) — выравнивание.

Тернарный оператор — условие ? значение1 : значение2. Например, ledState ? color(0,255,0) : color(255,0,0).

Пример 1: Передача данных с Arduino в Processing (График данных с потенциометра)

Концепции Processing в примере: arrays, map(), serialEvent(), beginShape()/endShape(), vertex(), background(), text().

Arduino-скетч:

void setup() {
  Serial.begin(9600);
}

  int sensorValue = analogRead(A0);
  Serial.println(sensorValue);

Processing-скетч:

import processing.serial.*;    // Подключаем Serial-библиотеку
Serial myPort;                  // Объект для работы с портом
float[] values = new float[100]; // Массив для хранения 100 последних значений
int index = 0;                  // Текущая позиция в массиве
void setup() {
  size(800, 400);
  // Замените "COM3" на ваш порт
  myPort = new Serial(this, "COM3", 9600);
  myPort.bufferUntil('\n');     // Собираем данные до символа новой строки
}
void draw() {
  background(255);
  // Рисуем график: соединяем точки линиями
  stroke(0, 150, 255);
  noFill();
  beginShape();
  for (int i = 0; i < values.length; i++) {
    // map() переводит 0-1023 в 0-height (инвертировано по Y)
    float y = map(values[i], 0, 1023, height, 0);
    vertex(map(i, 0, values.length, 0, width), y);
  }
  endShape();
  // Выводим текущее значение
  fill(0);
  // index указывает на следующую свободную ячейку,
  // поэтому последнее значение лежит на шаг раньше
  int last = (index - 1 + values.length) % values.length;
  text("Потенциометр: " + values[last], 20, 30);
}
// serialEvent() автоматически вызывается при получении данных из Serial
void serialEvent(Serial p) {
  String data = trim(p.readString());  // Читаем строку, убираем пробелы
  if (data != null) {
    float val = float(data);           // Преобразуем строку в число
    values[index] = val;               // Сохраняем в массив
    index = (index + 1) % values.length; // Циклический индекс
  }
}
ПОЯСНЕНИЕ
Почему trim() и bufferUntil(). Arduino отправляет число и символы конца строки \r\n. bufferUntil('\n') заставляет Processing вызвать serialEvent() только когда пришла целая строка, а не на каждый байт. trim() убирает невидимые \r и пробелы — без этого float("512\r") вернёт NaN. Функция trim() из Processing безопасна и для null, поэтому проверка data != null стоит после неё.

Разбор Processing-кода:

ПОЯСНЕНИЕ
Что здесь происходит. В этом примере Arduino выдаёт числа, Processing принимает очередную строку, превращает её в значение и уже после этого рисует график. Удобно мысленно разделять программу на три части: получить данные → проверить/преобразовать → визуализировать.

• import processing.serial.*; — библиотека для Serial-порта.

• Serial myPort; — переменная для работы с портом.

• bufferUntil('\n') — накапливает данные, пока не придёт \n, затем вызывает serialEvent().

• serialEvent() — встроенная функция Processing, срабатывает при получении данных.

• map(values[i], 0, 1023, height, 0) — преобразует 0–1023 в диапазон высоты окна.

• beginShape() / vertex() / endShape() — рисует ломаную линию по точкам.

Продвинутые проекты Processing + Arduino

В простых примерах достаточно отправлять одно число. В реальном проекте быстро появляются команды, несколько датчиков и ответы устройства. Поэтому здесь главное внимание не графике, а структуре обмена: как сформировать сообщение, разобрать его и не запутать разные типы данных.

Повторение: Processing для главы 21

В примерах этой главы используются следующие возможности Processing.

Классы и объекты — class Ball { ... }. Позволяют создавать свои типы данных для организации сложных проектов.

Строки и их методы:

• split(input, separator) — разбивает строку на массив по разделителю

• indexOf(char) — ищет позицию символа в строке

• substring(start, end) — вырезает часть строки

• toInt() — преобразует строку в целое число

• trim() — удаляет пробелы в начале и конце

Обработка клавиатуры:

• keyPressed() — вызывается при нажатии клавиши

• key — содержит нажатый символ

• keyCode — код клавиши (UP, DOWN, LEFT, RIGHT)

• key == ENTER / key == BACKSPACE — проверка спецклавиш

Тригонометрия для визуализации:

• sin(angle), cos(angle) — синус и косинус угла в радианах

• radians(degrees) — переводит градусы в радианы

• atan2(y, x) — угол вектора от начала координат до точки (x, y)

Визуализация данных:

• beginShape() / vertex() / endShape() — рисование произвольной ломаной

• map(value, fromLow, fromHigh, toLow, toHigh) — пересчёт диапазона

• lerpColor(c1, c2, t) — плавный переход между цветами

Таймеры и счётчики кадров:

• millis() — миллисекунды с запуска программы

• frameCount — количество прошедших кадров

• frameRate — частота кадров (по умолчанию 60)

Пример 4: Отправка текстовых команд на Arduino

Концепции Processing: строки, split(), keyPressed(), контроллеры мыши (mousePressed()), кастомные функции с отрисовкой кнопок.

В отличие от одиночных символов, текстовые команды позволяют передавать сложные инструкции: LED:1, SERVO:90, RGB:255,0,0.

Arduino-скетч (парсинг команд):

ПОЯСНЕНИЕ
Разбор. Текстовый протокол проще отлаживать, потому что команды можно увидеть в Serial Monitor. Главное заранее договориться о формате: где заканчивается команда, как отделяются аргументы и что устройство отвечает при ошибке.
void setup() {
  Serial.begin(9600);
  pinMode(13, OUTPUT);
}
void loop() {
  if (Serial.available() > 0) {
    // Serial.readStringUntil('\n') читает строку до символа \n
    String command = Serial.readStringUntil('\n');
    command.trim();
    if (command.startsWith("LED:")) {
      int value = command.substring(4).toInt();
      digitalWrite(13, value == 1 ? HIGH : LOW);
      Serial.println("LED:OK");
    }
    else if (command.startsWith("SERVO:")) {
      int angle = command.substring(6).toInt();
      // myServo.write(angle); — при подключённом сервоприводе
      Serial.println("SERVO:OK");
    }
    else if (command.startsWith("RGB:")) {
      String rgbStr = command.substring(4);
      int comma1 = rgbStr.indexOf(',');
      int comma2 = rgbStr.indexOf(',', comma1 + 1);
      int r = rgbStr.substring(0, comma1).toInt();
      int g = rgbStr.substring(comma1 + 1, comma2).toInt();
      int b = rgbStr.substring(comma2 + 1).toInt();
      Serial.println("RGB:OK");
    }
    else {
      Serial.println("ERROR:UNKNOWN_COMMAND");
    }
  }
}

Разбор Arduino-кода:

• Serial.readStringUntil('\n') — читает данные из Serial buffer до символа новой строки.

• command.startsWith("LED:") — проверяет префикс.

• command.substring(4).toInt() — извлекает число из строки после 4 символа.

• indexOf(',') — находит позицию запятой для разбора RGB.

Processing-скетч (панель управления):

import processing.serial.*;
Serial myPort;
String sendValue = "";
boolean inputMode = false;
String receivedData = "";
void setup() {
  size(400, 370);
  myPort = new Serial(this, "COM3", 9600);
  myPort.bufferUntil('\n');   // serialEvent() — только на целую строку
  surface.setTitle("Терминал команд");
}
void draw() {
  background(240);
  // Поле ввода
  fill(255);
  stroke(inputMode ? color(100, 150, 255) : color(180));
  strokeWeight(2);
  rect(20, 80, 360, 40, 5);
  fill(0);
  textAlign(LEFT, CENTER);
  textSize(18);
  // Мигающий курсор: каждые 15 кадров переключается видимость
  String cursor = (inputMode && frameCount % 30 < 15) ? "|" : "";
  text(sendValue + cursor, 30, 100);
  fill(100);
  textSize(14);
  text("Введите команду и нажмите ENTER", 20, 50);
  text("Примеры: LED:1, LED:0, SERVO:90, RGB:255,0,0", 20, 170);
  // Кнопки-шорткаты (первый ряд — LED и SERVO)
  drawShortcut(20, 200, 70, 30, "LED ON", "LED:1");
  drawShortcut(100, 200, 70, 30, "LED OFF", "LED:0");
  drawShortcut(180, 200, 90, 30, "SERVO 90", "SERVO:90");
  drawShortcut(280, 200, 90, 30, "SERVO 0", "SERVO:0");
  // Второй ряд — RGB цвета
  drawShortcut(20, 250, 90, 30, "RGB RED", "RGB:255,0,0");
  drawShortcut(120, 250, 90, 30, "RGB GREEN", "RGB:0,255,0");
  drawShortcut(220, 250, 90, 30, "RGB BLUE", "RGB:0,0,255");
  // Вывод ответа от Arduino
  fill(50);
  textAlign(LEFT, TOP);
  textSize(12);
  text("Ответ Arduino: " + receivedData, 20, 320);
}
void drawShortcut(int x, int y, int w, int h, String label, String cmd) {
  boolean hover = mouseX > x && mouseX < x + w && mouseY > y && mouseY < y + h;
  fill(hover ? 200 : 220);
  stroke(180);
  rect(x, y, w, h, 4);
  fill(0);
  textAlign(CENTER, CENTER);
  textSize(12);
  text(label, x + w / 2, y + h / 2);
}
void mousePressed() {
  inputMode = (mouseX > 20 && mouseX < 380 && mouseY > 80 && mouseY < 120);
  if (mouseY >= 200 && mouseY <= 230) {
    if (mouseX > 20 && mouseX < 90)      sendCommand("LED:1");
    else if (mouseX > 100 && mouseX < 170) sendCommand("LED:0");
    else if (mouseX > 180 && mouseX < 270) sendCommand("SERVO:90");
    else if (mouseX > 280 && mouseX < 370) sendCommand("SERVO:0");
  }
  if (mouseY >= 250 && mouseY <= 280) {
    if (mouseX > 20 && mouseX < 110)     sendCommand("RGB:255,0,0");
    else if (mouseX > 120 && mouseX < 210) sendCommand("RGB:0,255,0");
    else if (mouseX > 220 && mouseX < 310) sendCommand("RGB:0,0,255");
  }
}
void keyPressed() {
  if (inputMode) {
    if (key == ENTER || key == RETURN) {
      sendCommand(sendValue);
      sendValue = "";
    } else if (key == BACKSPACE && sendValue.length() > 0) {
      sendValue = sendValue.substring(0, sendValue.length() - 1);
    } else if (key != CODED) {
      sendValue += key;
    }
  }
}
void sendCommand(String cmd) {
  println("Отправка: " + cmd);
  myPort.write(cmd + "\n");
}
void serialEvent(Serial p) {
  String data = trim(p.readString());
  if (data != null) receivedData = data;
}

Как это работает:

• Пользователь вводит текстовую команду (например, LED:1) и нажимает Enter.

• Processing отправляет: myPort.write("LED:1\n").

• Arduino получает через Serial.readStringUntil('\n'), проверяет префикс и выполняет действие.

• Arduino отправляет подтверждение (LED:OK), Processing отображает его.

• Кнопки-шорткаты отправляют команды одним кликом.

Пример 5: Двусторонняя связь — опрос датчиков по запросу

Концепции Processing: keyPressed(), кнопки мыши, serialEvent(), функция split().

Вместо непрерывного потока данных можно опрашивать датчики только когда нужно.

ПОЯСНЕНИЕ
Что здесь происходит. Это схема запрос → ответ. Processing отправляет команду, Arduino измеряет значения и отвечает одной строкой. Такой обмен проще контролировать, когда не нужен постоянный поток данных.

Processing-скетч:

import processing.serial.*;
Serial myPort;
String sensorData = "Нажмите R для запроса";
void setup() {
  size(400, 300);
  myPort = new Serial(this, "COM3", 9600);
  myPort.bufferUntil('\n');
  surface.setTitle("Опрос датчиков");
}
void draw() {
  background(240);
  fill(0);
  textSize(16);
  text("Данные с Arduino:", 20, 50);
  textSize(14);
  text(sensorData, 20, 100);
  // Кнопка запроса (прямоугольник + текст)
  fill(100, 150, 255);
  rect(20, 200, 120, 40, 5);
  fill(255);
  textAlign(CENTER, CENTER);
  text("Запросить (R)", 80, 220);
}
void keyPressed() {
  if (key == 'r' || key == 'R') {
    myPort.write("READ\n");
  }
}
void mousePressed() {
  if (mouseX > 20 && mouseX < 140 && mouseY > 200 && mouseY < 240) {
    myPort.write("READ\n");
  }
}
void serialEvent(Serial p) {
  String data = trim(p.readString());
  if (data != null && data.length() > 0) {
    sensorData = data;
    // При желании: String[] parts = split(data, " | ");
    println("Получено: " + data);
  }
}

Arduino-скетч:

void setup() {
  Serial.begin(9600);
}
void loop() {
  if (Serial.available() > 0) {
    String cmd = Serial.readStringUntil('\n');
    cmd.trim();
    if (cmd.equals("READ")) {
      Serial.print("A0:");
      Serial.print(analogRead(A0));
      Serial.print(" | A1:");
      Serial.print(analogRead(A1));
      Serial.print(" | A2:");
      Serial.println(analogRead(A2));
    }
  }
}

Как это работает:

• Пользователь нажимает R (или кнопку) — Processing отправляет READ.

• Arduino получает команду, читает все аналоговые пины и отправляет одной строкой.

• Processing принимает в serialEvent() и выводит на экран.

Пример 6: Ультразвуковой дальномер HC-SR04 + Визуализация

Концепции Processing: arc(), map(), colorMode(HSB), translate(), тригонометрия.

HC-SR04 измеряет расстояние от 2 до 400 см методом эхолокации.

Схема подключения:

HC-SR04Arduino
VCC5V
GNDGND
TRIG9
ECHO10

Arduino-скетч:

const int TRIG = 9;
const int ECHO = 10;
void setup() {
  Serial.begin(9600);
  pinMode(TRIG, OUTPUT);
  pinMode(ECHO, INPUT);
}
void loop() {
  digitalWrite(TRIG, LOW);
  delayMicroseconds(2);
  digitalWrite(TRIG, HIGH);
  delayMicroseconds(10);
  digitalWrite(TRIG, LOW);
  long duration = pulseIn(ECHO, HIGH);
  float distance = duration * 0.034 / 2;  // см
  Serial.println(distance);
  delay(200);
}

Разбор: pulseIn(ECHO, HIGH) замеряет длительность импульса в микросекундах. Скорость звука ~340 м/с = 0.034 см/мкс. Делим на 2, так как сигнал идёт туда и обратно.

Processing-скетч (радар):

ЗАМЕТКА
Мини-проверка. Перед запуском радара отдельно проверь, что в консоль приходят корректные угол и расстояние. Если данные уже неверные на входе, проблема не в отрисовке радара.
import processing.serial.*;
Serial myPort;
float distance = 0;
float angle = 0;
void setup() {
  size(500, 500);
  myPort = new Serial(this, "COM3", 9600);
  myPort.bufferUntil('\n');
  colorMode(HSB, 360, 100, 100);
}
void draw() {
  background(0);
  translate(width / 2, height - 50);  // Начало координат — внизу по центру
  // Шкалы радара (полукруги)
  noFill();
  stroke(60);
  strokeWeight(1);
  for (int r = 50; r <= 200; r += 50) {
    arc(0, 0, r * 2, r * 2, PI, TWO_PI);
  }
  // Точка обнаружения
  if (distance > 0) {
    float d = constrain(map(distance, 0, 50, 0, 200), 0, 200);
    float hue = map(distance, 5, 50, 0, 120);  // 0=красный, 120=зелёный
    stroke(hue, 100, 100);
    strokeWeight(8);
    float px = cos(radians(angle - 90)) * d;
    float py = sin(radians(angle - 90)) * d;
    point(px, py);
  }
  // Вращающийся луч
  stroke(0, 100, 100, 50);
  strokeWeight(2);
  line(0, 0, cos(radians(angle - 90)) * 200, sin(radians(angle - 90)) * 200);
  angle = (angle + 2) % 360;
  // Текст
  resetMatrix();
  fill(255);
  textAlign(CENTER, TOP);
  textSize(16);
  text("Расстояние: " + nf(distance, 0, 1) + " см", width / 2, 20);
}
void serialEvent(Serial p) {
  String data = trim(p.readString());
  if (data != null && data.length() > 0) {
    float val = float(data);
    if (val > 0) distance = val;
  }
}

Разбор Processing-кода:

• translate(width/2, height-50) — перенос начала координат для удобства отрисовки радара.

• arc(0, 0, r*2, r*2, PI, TWO_PI) — полукруг (верхняя половина).

• cos(radians(angle)) * d — вычисление координат точки под углом.

Пример 7: Датчик температуры DHT11 с графиком

Концепции Processing: rect() для столбцов, lerpColor(), массивы-кольцевые буферы, split().

DHT11 — цифровой датчик температуры (0–50°C) и влажности (20–90%).

Схема подключения:

DHT11Arduino
VCC5V
GNDGND
DATA7

Между DATA и VCC желателен резистор 10 кОм.

Arduino-скетч:

#include <DHT.h>
#define DHTPIN 7
#define DHTTYPE DHT11
DHT dht(DHTPIN, DHTTYPE);
void setup() {
  Serial.begin(9600);
  dht.begin();
}
void loop() {
  float temperature = dht.readTemperature();
  float humidity = dht.readHumidity();
  if (!isnan(temperature) && !isnan(humidity)) {
    Serial.print(temperature);
    Serial.print(" ");
    Serial.println(humidity);
  }
  delay(2000);
}

Разбор: dht.readTemperature() возвращает температуру в °C, dht.readHumidity() — влажность в %. isnan() проверяет, что значения корректны.

Processing-скетч (график температуры и влажности):

ПОЯСНЕНИЕ
Разбор. График не должен знать, откуда пришло значение. Он получает число и рисует его. Такой принцип полезен в проектах: отдельно чтение датчика, отдельно хранение истории, отдельно визуализация.
import processing.serial.*;
Serial myPort;
float temperature = 0;
float humidity = 0;
// Кольцевой буфер на 60 значений
float[] tempHistory = new float[60];
float[] humHistory = new float[60];
int historyIndex = 0;
void setup() {
  size(600, 400);
  myPort = new Serial(this, "COM3", 9600);
  myPort.bufferUntil('\n');
  surface.setTitle("Монитор температуры и влажности");
}
void draw() {
  background(240);
  // Текущие значения (левый столбец)
  textSize(14);
  fill(0);
  text("Температура", 30, 30);
  textSize(36);
  fill(lerpColor(color(0, 100, 255), color(255, 50, 0),
       constrain(temperature / 40, 0, 1)));
  text(nf(temperature, 0, 1) + "°C", 30, 80);
  textSize(14);
  fill(0);
  text("Влажность", 30, 130);
  textSize(36);
  fill(0, 100, 200);
  text(nf(humidity, 0, 1) + "%", 30, 180);
  // График (правый столбец)
  int gx = 200, gy = 30, gw = 370, gh = 340;
  fill(255);
  stroke(200);
  rect(gx, gy, gw, gh);
  // Температура — красная линия
  stroke(255, 50, 0);
  strokeWeight(2);
  noFill();
  beginShape();
  for (int i = 0; i < tempHistory.length; i++) {
    int idx = (historyIndex + i) % tempHistory.length;
    float x = map(i, 0, tempHistory.length - 1, gx, gx + gw);
    float y = map(tempHistory[idx], 0, 50, gy + gh, gy);
    vertex(x, y);
  }
  endShape();
  // Влажность — синяя линия
  stroke(0, 100, 200);
  beginShape();
  for (int i = 0; i < humHistory.length; i++) {
    int idx = (historyIndex + i) % humHistory.length;
    float x = map(i, 0, humHistory.length - 1, gx, gx + gw);
    float y = map(humHistory[idx], 0, 100, gy + gh, gy);
    vertex(x, y);
  }
  endShape();
  // Легенда
  noStroke();
  fill(255, 50, 0);
  textSize(12);
  textAlign(LEFT, TOP);
  text("Температура", gx + 10, gy + 10);
  fill(0, 100, 200);
  text("Влажность", gx + 10, gy + 30);
}
void serialEvent(Serial p) {
  String data = trim(p.readString());
  if (data != null && data.length() > 0) {
    // split() разбивает строку на две части: "25.3 60.1"
    String[] parts = split(data, ' ');
    if (parts.length >= 2) {
      temperature = float(parts[0]);
      humidity = float(parts[1]);
      // Кольцевой буфер: сохраняем и сдвигаем индекс
      tempHistory[historyIndex] = temperature;
      humHistory[historyIndex] = humidity;
      historyIndex = (historyIndex + 1) % tempHistory.length;
    }
  }
}

Разбор Processing-кода:

• split(data, ' ') — разбивает строку "25.3 60.1" на массив ["25.3", "60.1"].

• lerpColor(blue, red, t) — плавный переход от синего к красному в зависимости от температуры.

• Кольцевой буфер: последние 60 значений хранятся в массиве; historyIndex циклически перезаписывает старые данные.

• beginShape() / vertex() / endShape() строит линию графика по точкам.

В финальном проекте соберём знакомые темы в одно приложение: состояние, события мыши, функции, цвета и элементы интерфейса. Полезнее всего смотреть на Paint не как на большой лист кода, а как на несколько маленьких задач, которые соединены вместе.

int brushColor = color(0);
int brushSize = 5;
boolean isDrawing = false;
boolean eraserMode = false;
void setup() {
  size(800, 600);
  background(255);
}
void draw() {
  if (isDrawing) {
    if (eraserMode) {
      stroke(255);
    } else {
      stroke(brushColor);
    }
    strokeWeight(brushSize);
    line(mouseX, mouseY, pmouseX, pmouseY);
  }
  drawPalette();
}
void mousePressed() {
  if (mouseY < height - 50) {
    isDrawing = true;
  } else {
    if (mouseX < width / 5) {
      brushColor = color(255, 0, 0);
    } else if (mouseX < 2 * width / 5) {
      brushColor = color(0, 255, 0);
    } else if (mouseX < 3 * width / 5) {
      brushColor = color(0, 0, 255);
    } else if (mouseX < 4 * width / 5) {
      brushColor = color(255, 255, 0);
    } else {
      brushColor = color(0);
    }
  }
}
void mouseReleased() {
  isDrawing = false;
}
void drawPalette() {
  noStroke();                 // иначе палитра унаследует обводку кисти
  fill(255);
  rect(0, height - 50, width, 50);
  fill(255, 0, 0);
  rect(0, height - 50, width / 5, 50);
  fill(0, 255, 0);
  rect(width / 5, height - 50, width / 5, 50);
  fill(0, 0, 255);
  rect(2 * width / 5, height - 50, width / 5, 50);
  fill(255, 255, 0);
  rect(3 * width / 5, height - 50, width / 5, 50);
  fill(0);
  rect(4 * width / 5, height - 50, width / 5, 50);
  fill(eraserMode ? 160 : 200);
  rect(width - 100, height - 50, 100, 50);
  fill(0);
  textAlign(CENTER, CENTER);
  text("Ластик", width - 50, height - 25);
  // индикатор текущей кисти — над палитрой, чтобы его не закрывали кнопки
  fill(255);
  rect(width - 70, height - 120, 60, 60);
  stroke(180);
  strokeWeight(1);
  fill(eraserMode ? color(255) : brushColor);
  ellipse(width - 40, height - 90, min(brushSize * 2, 50), min(brushSize * 2, 50));
  noStroke();
}
void mouseWheel(MouseEvent event) {
  brushSize += event.getCount();
  brushSize = constrain(brushSize, 1, 50);
}
void mouseClicked() {
  if (mouseX > width - 100 && mouseX < width && mouseY > height - 50 && mouseY < height) {
    eraserMode = !eraserMode;
  }
}

Разбор ключевых моментов:

ПОЯСНЕНИЕ
Разбор. Если код Paint кажется большим, раздели его на четыре части: состояние кисти, рисование холста, обработка мыши и клавиш, интерфейс палитры. После такого разбиения каждая часть уже знакома по предыдущим главам.

• setup() — задаёт размер окна и белый фон.

• draw() — проверяет, рисуем ли мы (isDrawing), и проводит линию от предыдущей позиции к текущей.

• Обработка мыши — mousePressed() переключает цвет или включает рисование; mouseWheel() меняет размер кисти; mouseClicked() включает ластик.

• Палитра — 5 цветных кнопок внизу экрана.

• Ластик — переключает цвет обводки на белый.

ЗАМЕТКА
Попробуй изменить. Сделай ластик не отдельным инструментом, а обычным цветом brushColor = color(255). Затем добавь индикатор активного цвета. Это небольшое изменение хорошо показывает, как интерфейс связан с состоянием программы.

Что такое Processing for Android

Мысленная модель важнее набора команд: если ты понимаешь слои, ошибка перестаёт выглядеть случайной.

Processing for Android — это Android Mode для Processing PDE. Он позволяет писать Processing-sketch в привычной модели setup()/draw(), а затем запускает Android-инструменты, чтобы получить приложение. При этом большая часть обычной Processing API остаётся доступной, а Android Mode добавляет Android-специфичные функции и возможность напрямую использовать классы Android SDK. [S1][S2]

Модель сборки

Sketch (.pde)
    ↓  Processing preprocessor
Java-код
    ↓  Android build
Gradle + Android SDK
    ↓
DEX + ресурсы + manifest
    ↓
APK
    ↓  adb
Телефон / эмулятор
ПОЯСНЕНИЕ
Как читать эту схему. Каждая стрелка — отдельный инструмент. Preprocessor превращает твой sketch в обычный Java-класс, наследующий PApplet. Gradle вместе с Android SDK компилирует его, переводит байткод в формат DEX (его исполняет Android Runtime), добавляет ресурсы и AndroidManifest.xml и упаковывает всё в APK. adb доставляет APK на устройство. Если ошибка возникла, первым делом определи, на какой стрелке она произошла, — это сразу сужает поиск.

24.1 Что Processing делает хорошо

• 2D/3D-графика, анимация, creative coding и нестандартные интерфейсы;

• визуализация сенсорных или телеметрических данных;

• быстрые прототипы, где важнее логика и графика, чем стандартные Android-экраны;

• интерактивные инсталляции и companion-приложения для устройств;

• обучение: можно быстро увидеть связь кода, графики, touch и физических сенсоров.

24.2 Где становится трудно

Как только приложение превращается в обычный сложный Android-продукт — много экранов, формы, списки, фоновые сервисы, push, deep links, сложная работа с разрешениями, современный Jetpack — PDE начинает скрывать слишком много деталей. В этот момент полезно либо экспортировать Android-проект, либо перейти в Android Studio и использовать Processing Core только для визуальной части.

ЗАМЕТКА
Практическая граница. Если 70–80% продукта — графическая сцена/визуализация, Processing обычно остаётся удобным. Если 70–80% — стандартный мобильный UI и Android-инфраструктура, Processing лучше оставить отдельным renderer-компонентом.
ИТОГИ

25.2 compileSdk, targetSdk и minSdk — не одно и то же

• compileSdk — версия Android API, против которой компилируется код;

• targetSdk — версия поведения Android, под которую приложение заявляет совместимость; именно к ней Google Play предъявляет требования;

• minSdk — самая старая версия Android, на которой приложение разрешено устанавливать.

Всегда выполняется соотношение minSdk ≤ targetSdk ≤ compileSdk. Пример: minSdk 26, targetSdk 36, compileSdk 36 означает, что приложение ставится на Android 8.0 и новее, ведёт себя по правилам Android 16 и может вызывать API вплоть до Android 16 (с проверкой версии на старых устройствах).

Установка и первый запуск

Настрой один стабильный путь SDK/JDK, затем проверяй слои по очереди.

26.1 Processing и Android Mode

• Установи Processing 4.x с официального сайта.

• В PDE открой selector режима → Manage Modes / Contribution Manager.

• Установи последнюю стабильную версию Android Mode и переключись в неё.

• При первом запуске выбери автоматическую установку SDK либо укажи уже установленный SDK. Официальный getting started требует, чтобы вручную выбранный SDK содержал Android 8.0 (API 26) или новее. [S5]

26.2 JDK

Для текущей ветки Android Mode ориентируйся на JDK 17. Проверка на macOS/Linux:

java -version
# macOS: показать установленные JDK
/usr/libexec/java_home -V
# выбрать JDK 17 на текущую shell-сессию
export JAVA_HOME=$(/usr/libexec/java_home -v 17)

На Windows то же самое делается в PowerShell:

java -version
# JDK 17 только для текущего окна PowerShell
$env:JAVA_HOME = "C:\Program Files\Eclipse Adoptium\jdk-17"
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
# навсегда для пользователя (подействует в новых окнах)
setx JAVA_HOME "C:\Program Files\Eclipse Adoptium\jdk-17"
ПОЯСНЕНИЕ
Зачем вообще JAVA_HOME?. Processing запускает Gradle, а Gradle ищет Java сначала в переменной JAVA_HOME, потом в PATH. Если на компьютере несколько JDK (например, 8, 17 и 21), именно JAVA_HOME решает, какая версия будет использована. Путь к JDK у тебя может отличаться — проверь папку установки.

26.3 Реальный телефон

• Включи Developer options: Настройки → О телефоне → семь раз нажми на «Номер сборки».

• Включи USB debugging: Настройки → Система → Для разработчиков → Отладка по USB (путь зависит от производителя).

• Подключи телефон data-кабелем (некоторые дешёвые кабели умеют только заряжать).

• Подтверди RSA-ключ компьютера на телефоне.

• Проверь соединение командой adb devices.

adb devices
# Нормально:
List of devices attached
R58...    device
# Нужно подтвердить телефон:
R58...    unauthorized

ADB входит в Android SDK Platform-Tools; Android Developers прямо рекомендует adb devices как базовую проверку соединения. [S8]

26.4 Первый sketch

void setup() {
  fullScreen();
  noStroke();
}
void draw() {
  background(24);
  fill(80, 200, 255);
  circle(mouseX, mouseY, 120);
}

Сохрани sketch до запуска. Затем выбери Run on Device. На этом этапе цель не «сделать приложение», а доказать, что цепочка PDE → SDK → Gradle → ADB работает целиком.

ПОЯСНЕНИЕ
Почему mouseX работает на телефоне?. Android Mode эмулирует мышь: при касании mouseX/mouseY получают координаты первого пальца, а mousePressed становится true. Для одного пальца этого достаточно. Для нескольких пальцев используется массив touches[] — он разобран в главе про экран и touch.

Если устройства нет под рукой, можно использовать эмулятор (Run in Emulator). Он медленнее и не имеет реальных сенсоров, поэтому для проектов с акселерометром, Bluetooth или камерой лучше сразу тестировать на телефоне.

27.1 Несколько .pde-файлов

Вкладки .pde удобны для организации кода, но не являются независимыми модулями. Processing preprocesses их как один sketch. Поэтому глобальные функции и переменные из одной вкладки видны из другой. Это удобно на маленьком проекте, но требует дисциплины именования.

ПОЯСНЕНИЕ
Что происходит с вкладками при сборке. Preprocessor склеивает все вкладки в один Java-файл: глобальные переменные и функции становятся полями и методами класса MotionScope extends PApplet, а классы из вкладок — его внутренними классами. Отсюда два следствия: имена не должны повторяться между вкладками, а внутренние классы могут обращаться к width, height и другим полям sketch напрямую.
ЗАМЕТКА
Правило. Разделяй по ответственности, а не по размеру: UI.pde рисует, Sensors.pde получает данные, Config.pde загружает конфиг. Не делай Tabs1.pde, Tabs2.pde без смысла.

27.2 data/

data/ предназначена для ресурсов, которые приложение читает во время работы: изображения, JSON, шрифты, таблицы, шейдеры. В коде обычно используется только имя файла: loadImage("logo.png"), loadJSONObject("config.json"). Не загружай один и тот же тяжёлый ресурс каждый frame.

PImage logo;
void setup() {
  fullScreen();
  logo = loadImage("logo.png");
}
void draw() {
  background(0);
  image(logo, 24, 24);
}

27.3 code/

В code/ можно помещать дополнительные JAR, но совместимость с desktop Java не гарантируется. Библиотека, которая использует Swing, AWT, JavaFX или desktop-native binaries, скорее всего не заработает на Android. Pure Java-библиотеки часто переносятся легче; всё равно проверяй их transitive dependencies.

ИТОГИ
Итоги главы 27
• Главный .pde-файл называется так же, как папка sketch.
• Все вкладки .pde склеиваются в один класс — имена не должны повторяться.
• data/ — ресурсы только для чтения, code/ — дополнительные JAR.
• Библиотеки с AWT, Swing или JavaFX на Android не работают.

31.1 Почему ./gradlew, а не gradle

Wrapper привязан к версии Gradle, ожидаемой проектом. Это делает сборку воспроизводимой и избавляет от зависимости от глобального gradle в системе. Android Developers рекомендует запускать задачи через wrapper. [S9]

./gradlew tasks

ПОЯСНЕНИЕ
Debug APK после сборки. После ./gradlew assembleDebug готовый файл лежит в app/build/outputs/apk/debug/app-debug.apk. Его можно установить командой adb install -r app/build/outputs/apk/debug/app-debug.apk или просто переслать на телефон и открыть (потребуется разрешить установку из неизвестных источников).

APK удобно устанавливать напрямую. AAB предназначен прежде всего для публикации: Google Play на его основе генерирует оптимизированные APK для конкретных устройств. AAB нельзя просто установить adb install как обычный APK. [S13]

Экран, density, touch и адаптивный UI

Android-экран — это не «1920×1080 и всё». Разные плотности и пропорции быстро ломают интерфейс с фиксированными числами.

32.1 fullScreen и orientation

void setup() {
  fullScreen(P2D);
  orientation(PORTRAIT);
}

В Android Mode orientation(PORTRAIT/LANDSCAPE) фиксирует ориентацию. Официальная справка подчёркивает, что автоповорот может перезапускать Activity, поэтому для многих визуализаторов фиксированная ориентация упрощает lifecycle. [S11]

32.2 displayDensity

Android Mode предоставляет displayDensity — коэффициент плотности. Он полезен для размеров текста и touch-targets, но для layout часто ещё важнее опираться на width/height. Официальные примеры масштабируют шрифты как 24 * displayDensity. [S7]

ПОЯСНЕНИЕ
Что такое density на практике. Android измеряет интерфейс в dp (density-independent pixels): 1 dp ≈ 1/160 дюйма. displayDensity показывает, сколько физических пикселей приходится на 1 dp: на экране 160 dpi это 1.0, на типичном современном телефоне — 2.5–3.5. Поэтому кнопка размером 48 * displayDensity будет иметь примерно одинаковый физический размер (около 7–9 мм — рекомендуемый минимум для пальца) на любом экране.

32.3 Почему фиксированные пиксели плохи

// Плохо для разных экранов
rect(100, 650, 300, 90);
// Лучше: доли доступного экрана
float margin = width * 0.05;
float buttonW = width * 0.90;
float buttonH = min(width, height) * 0.12;
rect(margin, height - buttonH - margin, buttonW, buttonH);

32.4 Touch и multitouch

void touchStarted() {
  println("touch started");
}
void touchMoved() {
}
void touchEnded() {
}
void draw() {
  background(20);
  for (int i = 0; i < touches.length; i++) {
    circle(touches[i].x, touches[i].y, 40 * displayDensity);
  }
}

Android Mode имеет touches[] и callbacks touchStarted/touchMoved/touchEnded. Каждый touch содержит координаты, area, pressure и id. [S7]

ПОЯСНЕНИЕ
mouseX или touches[]?. touches[] — это массив пальцев, которые касаются экрана прямо сейчас; когда пальцев нет, его длина равна 0. Порядок элементов может меняться, поэтому, если нужно отслеживать конкретный палец между кадрами (например, для жеста «щипок»), опирайся на touches[i].id, а не на индекс i. Для простых кнопок и одного пальца достаточно mouseX/mouseY и mousePressed.

32.5 Пример: щипок для масштабирования

Классический жест двумя пальцами: масштаб меняется пропорционально изменению расстояния между ними.

float zoom = 1;
float startDist = -1;
float startZoom = 1;
void setup() {
  fullScreen();
}
void draw() {
  background(20);
  if (touches.length == 2) {
    float d = dist(touches[0].x, touches[0].y, touches[1].x, touches[1].y);
    if (startDist < 0) {          // жест только начался
      startDist = d;
      startZoom = zoom;
    }
    zoom = constrain(startZoom * d / startDist, 0.3, 5);
  } else {
    startDist = -1;               // пальцев не два — жест закончен
  }
  translate(width / 2, height / 2);
  scale(zoom);
  rectMode(CENTER);
  fill(80, 200, 255);
  rect(0, 0, 200, 200, 20);
}

32.6 Клавиатура и кнопка «Назад»

На телефоне нет физической клавиатуры, поэтому keyPressed() срабатывает только после того, как ты сам откроешь экранную клавиатуру через openKeyboard(). Закрыть её можно через closeKeyboard().

Системный жест или кнопка «Назад» по умолчанию закрывает приложение. В Android Mode его можно перехватить callback-функцией backPressed() — например, чтобы сначала закрыть внутреннее меню.

String input = "";
boolean menuOpen = false;
void setup() {
  fullScreen();
  textSize(24 * displayDensity);
}
void draw() {
  background(30);
  fill(255);
  text("Ввод: " + input, 40, 120);
  if (menuOpen) text("Меню открыто", 40, 200);
}
void mousePressed() {
  openKeyboard();             // показать экранную клавиатуру
}
void keyPressed() {
  if (key == ENTER) {
    closeKeyboard();
  } else if (key == BACKSPACE && input.length() > 0) {
    input = input.substring(0, input.length() - 1);
  } else if (key != CODED) {
    input += key;
  }
}
void backPressed() {
  // если меню открыто — закрываем его, иначе выходим из приложения
  if (menuOpen) {
    menuOpen = false;
  } else {
    getActivity().finish();
  }
}
ИТОГИ
Итоги главы 32
• fullScreen() и orientation() задают экран; фиксированная ориентация упрощает lifecycle.
• Размеры считайте в долях width/height или через displayDensity, а не в пикселях.
• touches[] хранит все пальцы, а mouseX/mouseY — первый палец.
• openKeyboard() показывает клавиатуру, backPressed() перехватывает кнопку «Назад».
Глава 33 · Processing for Android

Lifecycle, потоки и производительность

Большинство «странных зависаний» объясняются не Processing, а неправильной жизнью Activity или тяжёлой работой в кадре.

33.1 draw() — render loop

draw() вызывается много раз в секунду. Поэтому всё, что ты помещаешь туда, потенциально выполняется десятки раз в секунду. loadImage(), HTTP-запрос, открытие файла, создание крупных массивов и повторная инициализация сенсора внутри draw() — почти всегда ошибка.

// Плохо
void draw() {
  JSONObject data = loadJSONObject("https://example.com/api");
}
// Лучше: сеть/диск — по событию или в фоновой работе,
// draw() только читает уже подготовленное состояние.

33.2 Фоновая загрузка через thread()

В Processing есть простая функция thread("имяФункции"): она запускает указанную функцию sketch в отдельном потоке. Это самый короткий способ убрать сетевой запрос или чтение большого файла из draw().

JSONObject weather = null;      // результат — общий для потоков
volatile boolean loading = false;
void setup() {
  fullScreen();
  textSize(20 * displayDensity);
  startLoading();
}
void startLoading() {
  if (loading) return;          // не запускаем второй запрос параллельно
  loading = true;
  thread("loadWeather");        // loadWeather() выполнится в фоне
}
void loadWeather() {
  try {
    weather = loadJSONObject("https://example.com/api/weather.json");
  } catch (Exception e) {
    println("Ошибка сети: " + e.getMessage());
  }
  loading = false;
}
void draw() {
  background(25);
  fill(255);
  if (loading) {
    text("Загрузка...", 40, 100);
  } else if (weather == null) {
    text("Нет данных. Коснись, чтобы повторить", 40, 100);
  } else {
    text("Температура: " + weather.getFloat("temp"), 40, 100);
  }
}
void mousePressed() {
  if (!loading) startLoading();
}
ПОЯСНЕНИЕ
Почему здесь volatile. Поле loading меняют два потока: фоновый (loadWeather) и поток рисования (draw). Ключевое слово volatile гарантирует, что draw() увидит новое значение сразу, а не закэшированную копию. Для сетевого запроса не забудь включить разрешение INTERNET в Android → Sketch Permissions.

33.3 Lifecycle

Когда приложение уходит в фон, Activity получает pause. Сенсоры, камера, BLE scan и другие ресурсоёмкие подписки нужно остановить, а при resume — восстановить. Официальный tutorial сенсоров рекомендует unregisterListener() в onPause() и registerListener() в onResume(). [S10]

// onPause() и onResume() — методы PApplet, их можно
// переопределить прямо в sketch. super.* вызывать обязательно.
public void onPause() {
  if (sensorManager != null) {
    sensorManager.unregisterListener(listener);
  }
  super.onPause();
}
public void onResume() {
  super.onResume();
  if (sensorManager != null) {
    sensorManager.registerListener(listener, sensor, SensorManager.SENSOR_DELAY_GAME);
  }
}

33.4 Потоки

Sensor callbacks, network callbacks и Android APIs могут обновлять состояние асинхронно. Хорошая архитектура: callback быстро записывает новые значения в простые поля/очередь, а draw() читает их и рисует. Не выполняй тяжёлый renderer-код внутри callback.

ВНИМАНИЕ
ANR. Если main/UI thread блокируется слишком долго, Android может показать Application Not Responding. Причина часто не «медленный телефон», а синхронная сеть/диск/большой цикл в неподходящем месте.
ИТОГИ
Итоги главы 33
• В draw() нельзя грузить файлы, ходить в сеть и создавать тяжёлые объекты.
• thread() выносит долгую работу в фоновый поток; общие флаги помечайте volatile.
• В onPause() освобождайте сенсоры и подписки, в onResume() восстанавливайте; super.* обязателен.
• Блокировка главного потока приводит к ANR.

Manifest и permissions

Permission — это не одна галочка. Для dangerous permissions обычно есть declaration и runtime request.

В Android 6+ dangerous permissions запрашиваются во время работы. В Processing Android для этого предусмотрены requestPermission() и hasPermission(); при этом permission также должен быть выбран/объявлен для sketch. [S14][S15]

void setup() {
  fullScreen();
  requestPermission(
    "android.permission.ACCESS_FINE_LOCATION",
    "initLocation"
  );
}
void initLocation(boolean granted) {
  if (granted) {
    println("permission granted");
  } else {
    println("permission denied");
  }
}

Callback, переданный вторым аргументом requestPermission, должен принимать boolean. Инициализировать защищённый API лучше только после granted=true. Официальный location tutorial использует именно эту модель. [S14]

ПОЯСНЕНИЕ
Где объявить permission. В PDE открой меню Android → Sketch Permissions и отметь нужные пункты (например, ACCESS_FINE_LOCATION, CAMERA, INTERNET). Processing добавит их в AndroidManifest.xml. Без этой галочки requestPermission() не покажет диалог: Android просто откажет, потому что разрешения нет в manifest.

Если пользователь уже дал разрешение раньше, повторный диалог не нужен. Проверить текущее состояние можно через hasPermission():

void setup() {
  fullScreen();
  if (hasPermission("android.permission.CAMERA")) {
    initCamera();
  } else {
    requestPermission("android.permission.CAMERA", "onCameraPermission");
  }
}
void onCameraPermission(boolean granted) {
  if (granted) initCamera();
  else println("Без камеры этот экран недоступен");
}
void initCamera() {
  // здесь безопасно обращаться к камере
}

34.1 Почему возникает SecurityException

• permission не объявлен в manifest/selector;

• runtime permission не запрошен;

• пользователь отказал;

• в новой версии Android набор permissions изменился (особенно Bluetooth, media/storage, notifications);

• код вызвал защищённый API до завершения permission callback.

34.2 Не проси всё сразу

Запрашивай разрешение в момент, когда пользователь понимает, зачем оно нужно. Это лучше и для UX, и для диагностики: если камера нужна только на экране сканирования, запроси CAMERA при входе туда, а не при первом запуске приложения.

ИТОГИ
Итоги главы 34
• Опасные разрешения нужно и объявить (Sketch Permissions), и запросить во время работы.
• requestPermission() вызывает callback с boolean; hasPermission() проверяет текущее состояние.
• SecurityException почти всегда означает, что разрешение не объявлено, не запрошено или отклонено.

Сенсоры

Сенсорный проект — один из лучших сценариев для Processing: Android получает физические данные, Processing быстро превращает их в визуализацию.

Processing не имеет отдельной высокоуровневой функции «дай акселерометр», но sketch может импортировать android.hardware.* и работать с SensorManager напрямую. Официальный tutorial показывает получение Context, SensorManager, Sensor и SensorEventListener. [S10]

import android.content.Context;
import android.hardware.Sensor;
import android.hardware.SensorEvent;
import android.hardware.SensorEventListener;
import android.hardware.SensorManager;
SensorManager manager;
Sensor sensor;
void setup() {
  fullScreen();
  Context context = getContext();
  manager = (SensorManager) context.getSystemService(Context.SENSOR_SERVICE);
  sensor = manager.getDefaultSensor(Sensor.TYPE_ACCELEROMETER);
}

Этот фрагмент только находит сенсор — данных он ещё не получает. Чтобы значения начали приходить, нужен слушатель (SensorEventListener) и его регистрация. Ниже — полный минимальный sketch: шарик катается по экрану при наклоне телефона.

35.1 Полный пример: шарик-уровень

import android.content.Context;
import android.hardware.Sensor;
import android.hardware.SensorEvent;
import android.hardware.SensorEventListener;
import android.hardware.SensorManager;
SensorManager manager;
Sensor sensor;
AccelListener listener;
volatile float ax, ay;          // пишет поток сенсора, читает draw()
float x, y, vx, vy;
void setup() {
  fullScreen();
  orientation(PORTRAIT);
  x = width / 2;
  y = height / 2;
  Context context = getContext();
  manager = (SensorManager) context.getSystemService(Context.SENSOR_SERVICE);
  sensor = manager.getDefaultSensor(Sensor.TYPE_ACCELEROMETER);
  listener = new AccelListener();
  if (sensor != null) {
    manager.registerListener(listener, sensor, SensorManager.SENSOR_DELAY_GAME);
  }
}
void draw() {
  background(20);
  if (sensor == null) {
    fill(255);
    text("Акселерометр не найден", 40, 80);
    return;
  }
  // ось X сенсора направлена вправо, но значение растёт при наклоне влево,
  // поэтому берём её со знаком минус; ось Y совпадает с экранной.
  vx = (vx - ax * 0.5) * 0.96;
  vy = (vy + ay * 0.5) * 0.96;
  x = constrain(x + vx, 0, width);
  y = constrain(y + vy, 0, height);
  fill(80, 200, 255);
  noStroke();
  circle(x, y, 40 * displayDensity);
}
class AccelListener implements SensorEventListener {
  public void onSensorChanged(SensorEvent event) {
    ax = event.values[0];
    ay = event.values[1];
  }
  public void onAccuracyChanged(Sensor s, int accuracy) { }
}
public void onPause() {
  if (manager != null) manager.unregisterListener(listener);
  super.onPause();
}
public void onResume() {
  super.onResume();
  if (manager != null && sensor != null) {
    manager.registerListener(listener, sensor, SensorManager.SENSOR_DELAY_GAME);
  }
}
ПОЯСНЕНИЕ
Как устроены оси. Для телефона в портретной ориентации: X направлена вправо, Y — вверх вдоль экрана, Z — из экрана на тебя. Экранная ось y в Processing направлена вниз, поэтому знаки часто приходится инвертировать. Коэффициент 0.96 — «трение»: без него шарик разгоняется бесконечно. Проверка sensor != null обязательна: на некоторых устройствах (и в эмуляторе) нужного сенсора может не быть.

35.2 Частота и батарея

SENSOR_DELAY_FASTEST, GAME, UI и NORMAL задают типовую скорость обновления. Чем быстрее — тем ниже задержка, но выше нагрузка и расход батареи. Для визуализации движения GAME часто разумный старт, для спокойного UI может хватить UI/NORMAL.

35.3 Сырые данные не равны «движению»

Акселерометр измеряет proper acceleration и содержит компоненту гравитации. Телефон, лежащий экраном вверх, обычно показывает около 9.81 м/с² по одной из осей. Если тебе нужна динамическая составляющая, придётся фильтровать гравитацию или использовать другие сенсоры/rotation vector в зависимости от задачи.

35.4 Фильтрация

float alpha = 0.14;
filtered += (raw - filtered) * alpha;

Это простейший low-pass фильтр. Он сглаживает шум, но добавляет задержку. Чем меньше alpha, тем сильнее сглаживание и тем более «ленивым» становится интерфейс.

ПОЯСНЕНИЕ
Как подобрать alpha. Каждое новое значение сдвигает filtered на долю alpha в сторону raw. При alpha = 0.14 и 60 кадрах в секунду значение «догоняет» резкое изменение примерно на 63% за 7 кадров (≈0.1 с). alpha = 1 — фильтра нет совсем, alpha = 0.02 — очень плавно, но с заметной задержкой около секунды.
ИТОГИ
Итоги главы 35
• Сенсоры доступны через SensorManager из android.hardware.
• Данные приходят в SensorEventListener; регистрируйте его и снимайте в onPause()/onResume().
• Акселерометр включает гравитацию; оси сенсора не совпадают с экранной осью y.
• Low-pass фильтр сглаживает шум ценой задержки; проверяйте sensor != null.

36.1 Файлы и data/

Ресурсы из data/ удобны как read-only assets. Для изменяемых пользовательских данных лучше использовать Android/Processing API хранения в доступной приложению области, учитывая scoped storage новых Android. Не пытайся обращаться к произвольным абсолютным путям как на desktop.

На Android функции saveStrings(), saveJSONObject() и loadStrings() с относительным именем файла работают с внутренней папкой приложения. Её не видно в файловом менеджере, но она сохраняется между запусками и удаляется вместе с приложением.

int launches = 0;
void setup() {
  fullScreen();
  textSize(24 * displayDensity);
  String[] saved = loadStrings("launches.txt");   // null, если файла ещё нет
  if (saved != null && saved.length > 0) launches = int(saved[0]);
  launches++;
  saveStrings("launches.txt", new String[] { str(launches) });
}
void draw() {
  background(30);
  fill(255);
  text("Запусков: " + launches, 40, 120);
}
ВНИМАНИЕ
data/ только для чтения. Файлы из data/ упакованы внутрь APK. Перезаписать их нельзя: saveStrings("config.json", ...) создаст новый файл во внутренней папке, а не изменит asset. Поэтому шаблон по умолчанию держи в data/, а изменённые пользователем настройки — во внутренней папке.

36.2 Сеть

Сетевые запросы не должны блокировать UI/render thread. INTERNET относится к normal permission и обычно не требует runtime-диалога, но запросы всё равно должны выполняться асинхронно, с timeout и обработкой отсутствия сети. Простейший способ — функция thread() из главы про lifecycle; полноценный пример обмена данными по Wi-Fi с микроконтроллером разобран в главе «Связь с Arduino и ESP32».

37.1 Пример: адаптивная кнопка вместо ControlP5

В главе 15 кнопки рисовались вручную или через ControlP5. На Android эта библиотека не работает, поэтому проще написать маленький класс. Размеры задаются в долях экрана, а реакция — на отпускание пальца, как у системных кнопок Android: если палец увели с кнопки, нажатие отменяется.

TouchButton playBtn, resetBtn;
int counter = 0;
void setup() {
  fullScreen();
  orientation(PORTRAIT);
  float w = width * 0.8;
  float h = 56 * displayDensity;            // ≈ 9 мм на любом экране
  playBtn  = new TouchButton("+1",    (width - w) / 2, height * 0.55, w, h);
  resetBtn = new TouchButton("Сброс", (width - w) / 2, height * 0.55 + h * 1.4, w, h);
  textAlign(CENTER, CENTER);
}
void draw() {
  background(24, 26, 32);
  fill(255);
  textSize(64 * displayDensity);
  text(counter, width / 2, height * 0.3);
  playBtn.display();
  resetBtn.display();
}
void mousePressed() {
  playBtn.press(mouseX, mouseY);
  resetBtn.press(mouseX, mouseY);
}
void mouseReleased() {
  if (playBtn.release(mouseX, mouseY))  counter++;
  if (resetBtn.release(mouseX, mouseY)) counter = 0;
}
class TouchButton {
  String label;
  float x, y, w, h;
  boolean pressed = false;
  TouchButton(String label, float x, float y, float w, float h) {
    this.label = label;
    this.x = x; this.y = y; this.w = w; this.h = h;
  }
  boolean over(float px, float py) {
    return px > x && px < x + w && py > y && py < y + h;
  }
  void press(float px, float py) {
    pressed = over(px, py);
  }
  // true — если палец отпущен над кнопкой (нажатие засчитано)
  boolean release(float px, float py) {
    boolean clicked = pressed && over(px, py);
    pressed = false;
    return clicked;
  }
  void display() {
    noStroke();
    fill(pressed ? color(50, 140, 220) : color(45, 50, 62));
    rect(x, y, w, h, h * 0.25);
    fill(255);
    textSize(h * 0.4);
    text(label, x + w / 2, y + h / 2);
  }
}
ПОЯСНЕНИЕ
Почему реакция на отпускание. Если засчитывать нажатие в mousePressed(), пользователь не сможет «передумать», а при прокрутке или случайном касании кнопка будет срабатывать сама. Схема press → release повторяет поведение стандартных кнопок Android и почти ничего не стоит.

37.2 Пример: перенос анимации с PVector

Код на PVector из главы 17 переносится без изменений. Единственное, что стоит поменять, — источник силы: вместо мыши можно использовать наклон телефона (см. главу про сенсоры) или палец.

PVector pos, vel;
void setup() {
  fullScreen();
  pos = new PVector(width / 2, height / 2);
  vel = new PVector(0, 0);
}
void draw() {
  noStroke();
  fill(20, 20, 30, 40);                     // полупрозрачный прямоугольник —
  rect(0, 0, width, height);                // «шлейф» (background() прозрачность игнорирует)
  if (mousePressed) {
    PVector target = new PVector(mouseX, mouseY);
    PVector force = PVector.sub(target, pos);
    force.setMag(0.6 * displayDensity);     // сила не зависит от расстояния
    vel.add(force);
  }
  vel.mult(0.97);                           // трение
  vel.limit(25 * displayDensity);
  pos.add(vel);
  noStroke();
  fill(255, 160, 60);
  circle(pos.x, pos.y, 30 * displayDensity);
}
ЗАМЕТКА
Проверка переноса. После переноса прогони sketch на двух устройствах с разной плотностью экрана (или в эмуляторе с другим профилем). Если что-то «уехало» или стало слишком мелким, ищи в коде числа-пиксели и заменяй их долями width/height или множителем displayDensity.

        │   ◀──────────────  "2731"     analogRead(34) каждые 50 мс

        │   "LED1" / "LED0" ────────▶   digitalWrite(LED_PIN, …)
ПОЯСНЕНИЕ
Почему телефон пишет первым. Узнать IP-адрес телефона из sketch неудобно, а IP платы ESP32 печатает в Serial Monitor при старте. Поэтому телефон отправляет плате короткий пакет HELLO, а плата отвечает на тот адрес и порт, с которого пакет пришёл. Так не нужно ничего вписывать вручную, кроме IP платы.

38.2 Скетч для ESP32 (Arduino IDE)

Подключи потенциометр к GPIO34 (средний вывод), крайние выводы — к 3.3 V и GND. Встроенный светодиод на большинстве плат ESP32 DevKit висит на GPIO2.

#include <WiFi.h>
#include <WiFiUdp.h>
const char* WIFI_SSID = "MyWiFi";
const char* WIFI_PASS = "password";
const int   UDP_PORT  = 4210;
const int   POT_PIN   = 34;
const int   LED_PIN   = 2;
WiFiUDP udp;
IPAddress phoneIp;
uint16_t phonePort = 0;
bool hasPhone = false;
unsigned long lastSend = 0;
void setup() {
  Serial.begin(115200);
  pinMode(LED_PIN, OUTPUT);
  WiFi.begin(WIFI_SSID, WIFI_PASS);
  while (WiFi.status() != WL_CONNECTED) {
    delay(300);
    Serial.print(".");
  }
  Serial.println();
  Serial.print("ESP32 IP: ");
  Serial.println(WiFi.localIP());   // этот адрес впиши в sketch на телефоне
  udp.begin(UDP_PORT);
}
void loop() {
  // 1. принимаем команды от телефона
  int size = udp.parsePacket();
  if (size > 0) {
    char buf[32];
    int n = udp.read(buf, sizeof(buf) - 1);
    buf[n] = 0;
    phoneIp   = udp.remoteIP();
    phonePort = udp.remotePort();
    hasPhone  = true;
    if (strcmp(buf, "LED1") == 0) digitalWrite(LED_PIN, HIGH);
    if (strcmp(buf, "LED0") == 0) digitalWrite(LED_PIN, LOW);
  }
  // 2. каждые 50 мс отправляем значение потенциометра (0..4095)
  if (hasPhone && millis() - lastSend >= 50) {
    lastSend = millis();
    udp.beginPacket(phoneIp, phonePort);
    udp.print(analogRead(POT_PIN));
    udp.endPacket();
  }
}

38.3 Sketch для телефона (Processing Android)

Перед запуском отметь разрешение INTERNET в Android → Sketch Permissions и впиши в ESP_IP адрес, который плата напечатала в Serial Monitor.

import java.net.DatagramPacket;
import java.net.DatagramSocket;
import java.net.InetAddress;
import java.net.SocketTimeoutException;
String ESP_IP   = "192.168.1.50";   // IP из Serial Monitor
int    ESP_PORT = 4210;
final int N = 100;                   // сколько точек на графике
int[] values = new int[N];
int head = 0;                        // кольцевой буфер, как в MotionScope
volatile boolean netRunning = false;
volatile int generation = 0;         // номер «поколения» сетевого потока
volatile long lastPacketMs = -100000;
volatile String pendingCommand = null;  // команда для фонового потока
boolean ledOn = false;
void setup() {
  fullScreen();
  orientation(PORTRAIT);
  textSize(18 * displayDensity);
  startNetwork();
}
void startNetwork() {
  if (netRunning) return;
  netRunning = true;
  generation++;
  thread("networkLoop");             // вся сеть — в фоновом потоке
}
void networkLoop() {
  int myGen = generation;            // старый поток не должен мешать новому
  DatagramSocket socket = null;
  try {
    InetAddress esp = InetAddress.getByName(ESP_IP);
    socket = new DatagramSocket();
    socket.setSoTimeout(200);        // receive() ждёт не дольше 200 мс
    byte[] buf = new byte[64];
    long lastHello = 0;
    while (netRunning && myGen == generation) {
      // HELLO раз в секунду, пока плата молчит (или после перезагрузки)
      if (millis() - lastPacketMs > 1000 && millis() - lastHello > 1000) {
        send(socket, esp, "HELLO");
        lastHello = millis();
      }
      String cmd = pendingCommand;
      if (cmd != null) {
        send(socket, esp, cmd);
        pendingCommand = null;
      }
      try {
        DatagramPacket p = new DatagramPacket(buf, buf.length);
        socket.receive(p);
        String s = new String(p.getData(), 0, p.getLength()).trim();
        int v = Integer.parseInt(s);
        synchronized (values) {
          values[head] = v;
          head = (head + 1) % N;
        }
        lastPacketMs = millis();
      } catch (SocketTimeoutException e) {
        // данных нет — просто идём на следующий круг
      } catch (NumberFormatException e) {
        // мусорный пакет — игнорируем
      }
    }
  } catch (Exception e) {
    println("Network error: " + e);
  } finally {
    if (socket != null) socket.close();
    if (myGen == generation) netRunning = false;
  }
}
void send(DatagramSocket socket, InetAddress addr, String msg) throws Exception {
  byte[] data = msg.getBytes();
  socket.send(new DatagramPacket(data, data.length, addr, ESP_PORT));
}
void draw() {
  background(18, 20, 26);
  boolean online = millis() - lastPacketMs < 1000;
  float m = width * 0.05;
  fill(online ? color(90, 220, 140) : color(230, 90, 90));
  text(online ? "ESP32 online" : "Нет связи с " + ESP_IP, m, m + 20 * displayDensity);
  // график последних N значений
  float gx = m, gy = height * 0.15, gw = width - 2 * m, gh = height * 0.45;
  noStroke();
  fill(31, 35, 45);
  rect(gx, gy, gw, gh, 12);
  stroke(80, 200, 255);
  strokeWeight(2 * displayDensity);
  noFill();
  beginShape();
  synchronized (values) {
    for (int i = 0; i < N; i++) {
      int v = values[(head + i) % N];
      vertex(map(i, 0, N - 1, gx, gx + gw), map(v, 0, 4095, gy + gh, gy));
    }
  }
  endShape();
  // кнопка LED
  float bh = 64 * displayDensity;
  float by = height - m - bh;
  noStroke();
  fill(ledOn ? color(255, 200, 60) : color(60, 66, 80));
  rect(m, by, width - 2 * m, bh, bh * 0.25);
  fill(ledOn ? 0 : 255);
  textAlign(CENTER, CENTER);
  text(ledOn ? "LED: ВКЛ" : "LED: ВЫКЛ", width / 2, by + bh / 2);
  textAlign(LEFT, BASELINE);
}
void mouseReleased() {
  float m = width * 0.05;
  float bh = 64 * displayDensity;
  if (mouseY > height - m - bh) {
    ledOn = !ledOn;
    pendingCommand = ledOn ? "LED1" : "LED0";   // отправит фоновый поток
  }
}
public void onPause() {
  netRunning = false;                   // поток сам закроет сокет
  super.onPause();
}
public void onResume() {
  super.onResume();
  startNetwork();
}

38.4 Разбор ключевых решений

• Вся работа с сетью вынесена в networkLoop(), запущенный через thread(). Если вызвать socket.send() прямо из mouseReleased(), Android может выбросить NetworkOnMainThreadException, а долгий receive() в draw() заморозил бы экран.

• Нажатие кнопки не отправляет пакет само, а кладёт команду в pendingCommand. Фоновый поток забирает её на следующем круге — не позже чем через 200 мс.

• Массив values читают два потока, поэтому запись и чтение обёрнуты в synchronized (values). Без этого график изредка рисовал бы «полузаписанные» данные.

• setSoTimeout(200) не даёт receive() зависнуть навсегда: поток регулярно проверяет флаг netRunning и может корректно завершиться в onPause(). Счётчик generation защищает от гонки: если приложение быстро свернули и развернули, старый поток увидит, что его «поколение» устарело, и тихо завершится, не трогая новый.

• Индикатор online основан на времени последнего пакета: если плату выключить, через секунду надпись станет красной, а телефон начнёт снова посылать HELLO.

• ESP32 возвращает 0..4095 (12-битный АЦП), поэтому в map() стоит 4095, а не 1023, как у Arduino Uno.

ВНИМАНИЕ
Если связи нет. Проверь по порядку: телефон и ESP32 в одной Wi-Fi сети (не гостевой — гостевые сети часто изолируют устройства друг от друга); IP в sketch совпадает с выводом Serial Monitor; разрешение INTERNET отмечено; ESP32 подключается к сети 2.4 ГГц (5 ГГц он не поддерживает). Для диагностики смотри adb logcat System.out:I *:S — туда попадает вывод println().

42.2 Sensors.pde

// Sensors.pde
import android.content.Context;
import android.hardware.Sensor;
import android.hardware.SensorEvent;
import android.hardware.SensorEventListener;
import android.hardware.SensorManager;
Context appContext;
SensorManager sensorManager;
Sensor accelerometer;
AccelerometerListener accelerometerListener;
volatile float rawAx = 0;
volatile float rawAy = 0;
volatile float rawAz = 0;
float ax = 0;
float ay = 0;
float az = 0;
float accelMagnitude = 0;
boolean sensorAvailable = false;
boolean sensorRegistered = false;
void initSensors() {
  appContext = getContext();
  sensorManager = (SensorManager) appContext.getSystemService(Context.SENSOR_SERVICE);
  accelerometer = sensorManager.getDefaultSensor(Sensor.TYPE_ACCELEROMETER);
  accelerometerListener = new AccelerometerListener();
  sensorAvailable = accelerometer != null;
  registerSensors();
}
void registerSensors() {
  if (!sensorAvailable || sensorManager == null) return;
  if (accelerometerListener == null) return;
  if (sensorRegistered) return;
  sensorManager.registerListener(
    accelerometerListener,
    accelerometer,
    SensorManager.SENSOR_DELAY_GAME
  );
  sensorRegistered = true;
}
void unregisterSensors() {
  if (sensorManager != null && accelerometerListener != null && sensorRegistered) {
    sensorManager.unregisterListener(accelerometerListener);
    sensorRegistered = false;
  }
}
void updateSensorModel() {
  if (freezeValues) return;
  ax += (rawAx - ax) * smoothing;
  ay += (rawAy - ay) * smoothing;
  az += (rawAz - az) * smoothing;
  accelMagnitude = sqrt(ax * ax + ay * ay + az * az);
}
class AccelerometerListener implements SensorEventListener {
  public void onSensorChanged(SensorEvent event) {
    rawAx = event.values[0];
    rawAy = event.values[1];
    rawAz = event.values[2];
  }
  public void onAccuracyChanged(Sensor sensor, int accuracy) {
  }
}
// Освобождаем сенсор в фоне, чтобы не расходовать батарею.
public void onPause() {
  unregisterSensors();
  super.onPause();
}
public void onResume() {
  super.onResume();
  registerSensors();
}
ПОЯСНЕНИЕ
Разбор Sensors.pde. Сенсор присылает данные в своём потоке, поэтому onSensorChanged() только копирует три числа в rawAx/rawAy/rawAz (volatile — чтобы draw() видел свежие значения). Вся математика — фильтр и модуль вектора — выполняется в updateSensorModel() внутри draw(), то есть в потоке рисования. Флаг sensorRegistered защищает от двойной регистрации: onResume() вызывается и при первом запуске, и после каждого возврата из фона.

42.3 Config.pde

// Config.pde
void loadAppConfig() {
  try {
    JSONObject config = loadJSONObject("config.json");
    if (config == null) return;
    if (config.hasKey("title")) {
      appTitle = config.getString("title");
    }
    if (config.hasKey("smoothing")) {
      smoothing = constrain(config.getFloat("smoothing"), 0.01, 1.0);
    }
  }
  catch (Exception e) {
    println("Config error: " + e.getMessage());
  }
}

Блок try/catch делает конфиг необязательным: если файла нет или в нём ошибка, приложение просто работает со значениями по умолчанию. constrain() защищает от бессмысленного smoothing вроде 0 или 5 — с такими значениями фильтр либо застынет, либо начнёт «раскачиваться».

42.4 History.pde

// History.pde
final int HISTORY_SIZE = 120;
float[] history = new float[HISTORY_SIZE];
int historyHead = 0;
void initHistory() {
  for (int i = 0; i < HISTORY_SIZE; i++) history[i] = 0;
}

  if (freezeValues) return;
  history[historyHead] = value;
  historyHead = (historyHead + 1) % HISTORY_SIZE;
}
ПОЯСНЕНИЕ
Кольцевой буфер. Вместо того чтобы при каждом новом значении сдвигать весь массив влево (120 операций на кадр), мы пишем значение по индексу historyHead и сдвигаем только сам индекс. Сборка, тестирование и расширение MotionScope

43.1 Запуск из Processing PDE

• Распакуй MotionScope так, чтобы папка и MotionScope.pde имели одинаковое имя.

• Открой MotionScope.pde в Processing и переключись в Android Mode.

• Подключи телефон и проверь adb devices.

• Выбери Run on Device.

• Поверни телефон: X/Y/Z и индикатор должны меняться. Коснись экрана — значения заморозятся.

43.2 Что проверять в logcat

Если приложение закрывается сразу, очисти лог, запусти его и сними новый вывод:

adb logcat -c

43.3 Эксперимент 1: чувствительность

Измени smoothing в data/config.json. Например 0.05 даст сильное сглаживание, 0.35 — более быструю реакцию. Это наглядно показывает компромисс noise ↔ latency.

43.4 Эксперимент 2: shake detector

boolean shake = accelMagnitude > 16.0;
if (shake) {
  // подсветить экран или записать событие
}

Порог 16 м/с² — только учебный пример: реальный threshold зависит от ориентации, устройства, фильтрации и того, нужно ли вычитать гравитацию.

43.5 Эксперимент 3: ориентация/гироскоп

Добавь второй Sensor для TYPE_GYROSCOPE или TYPE_ROTATION_VECTOR. Не смешивай сырые единицы измерения в одну переменную; создай отдельную модель данных и проверяй sensor != null, потому что набор сенсоров отличается у устройств.

43.6 Эксперимент 4: запись данных

Следующий шаг — накапливать timestamp + ax/ay/az и сохранять сессию. Делай запись пакетами, а не отдельной синхронной операцией на каждый кадр. Для полноценной истории поездок/тренировок лучше уже проектировать отдельный data layer.

Глава 44 · Processing for Android

Android Studio и Processing Core

Processing можно использовать не как IDE, а как графическую библиотеку внутри обычного Android-проекта.

Официальный tutorial рекомендует Android Studio для advanced Android development и описывает подключение processing-core.jar, после чего sketch реализуется классом, наследующим PApplet. [S16]

44.1 Когда переходить

• нужно targetSdk/compileSdk новее, чем поддерживает стабильный Mode;

• много Android dependencies/AAR и нужен нормальный dependency management;

• BLE, camera, WorkManager, notifications, services или Compose занимают большую часть проекта;

• нужны product flavors, CI/CD, instrumented tests, profiler;

• PDE скрывает причину сборочной ошибки и приходится постоянно править generated project.

44.2 Рекомендуемая архитектура

Android app
├── MainActivity / navigation
├── permissions
├── BLE / sensors / services
├── repository / storage
└── Processing renderer (PApplet)
        ↑
    получает готовое состояние

Это отделяет Android-инфраструктуру от визуализации. Processing перестаёт быть «всем приложением» и становится renderer-слоем, где он особенно силён.

44.3 Минимальный пример: PApplet внутри Activity

В Android Studio sketch — это обычный Java-класс. Главное отличие от PDE: размеры окна (fullScreen(), size()) и выбор renderer задаются в методе settings(), а не в setup() — в PDE это делал за тебя preprocessor. Все методы, которые переопределяют PApplet, должны быть public.

// Sketch.java
import processing.core.PApplet;
public class Sketch extends PApplet {
  public void settings() {
    fullScreen(P2D);
  }
  public void setup() {
    orientation(PORTRAIT);
  }
  public void draw() {
    background(24);
    fill(80, 200, 255);
    circle(mouseX, mouseY, 120);
  }
}

Sketch встраивается в Activity через PFragment:

// MainActivity.java
import android.os.Bundle;
import android.view.ViewGroup;
import android.widget.FrameLayout;
import androidx.appcompat.app.AppCompatActivity;
import processing.android.CompatUtils;
import processing.android.PFragment;
import processing.core.PApplet;
public class MainActivity extends AppCompatActivity {
  private PApplet sketch;
  @Override
  protected void onCreate(Bundle savedInstanceState) {
    super.onCreate(savedInstanceState);
    FrameLayout frame = new FrameLayout(this);
    frame.setId(CompatUtils.getUniqueViewId());
    setContentView(frame, new ViewGroup.LayoutParams(
        ViewGroup.LayoutParams.MATCH_PARENT,
        ViewGroup.LayoutParams.MATCH_PARENT));
    sketch = new Sketch();
    PFragment fragment = new PFragment(sketch);
    fragment.setView(frame, this);
  }
  // пробрасываем результат запроса разрешений в sketch
  @Override
  public void onRequestPermissionsResult(int requestCode,
      String[] permissions, int[] grantResults) {
    super.onRequestPermissionsResult(requestCode, permissions, grantResults);
    if (sketch != null) {
      sketch.onRequestPermissionsResult(requestCode, permissions, grantResults);
    }
  }
}
ПОЯСНЕНИЕ
Что даёт такая схема. FrameLayout можно положить в обычную разметку рядом с кнопками, списками или Compose-экраном. Activity отвечает за навигацию, разрешения и сервисы, а Sketch получает готовые данные (например, через public-поля или методы) и только рисует. Если processing-core.jar берёшь из Android Mode, положи его в app/libs/ и подключи строкой implementation files('libs/processing-core.jar') в app/build.gradle.
ВНИМАНИЕ
Старая документация. На официальной странице Android Studio всё ещё встречаются исторические упоминания Bintray. Для современного проекта ориентируйся на локальный processing-core.jar из Android Mode или на актуальную схему зависимостей проекта, а не на старый Bintray snippet.

Release, APK/AAB и Google Play

Debug APK — не релиз. Подпись, target API и формат доставки становятся отдельной частью работы.

45.1 Debug vs Release

45.2 Подписанная сборка из PDE

• В PDE открой Android → Sketch Properties и задай уникальный package name (например, com.yourname.motionscope), название и номер версии.

• Выбери File → Export Signed Bundle (AAB для Google Play) или Export Signed Package (APK для прямой установки).

• При первом экспорте Processing предложит создать keystore: придумай пароль и заполни данные владельца. Ключ сохраняется в настройках Processing — найди этот файл и сделай резервную копию.

• Готовый файл появится в папке sketch (подпапка buildBundle или build). Проверь APK на телефоне через adb install -r перед публикацией.

ВНИМАНИЕ
Package name нельзя поменять. После первой публикации в Google Play package name становится постоянным идентификатором приложения. Не оставляй автоматически сгенерированное имя вида processing.test.*.

45.3 Google Play в 2026

Начиная с 31 августа 2026 Google Play требует target API 36 для новых приложений и обновлений обычных Android-приложений; для существующих приложений действует отдельное требование доступности новым пользователям. [S12]

Поэтому перед публикацией обязательно проверяй фактические compileSdk/targetSdk итогового Android-проекта, а не только версию Android, на которой приложение запустилось.

45.4 Keystore

Release key — часть идентичности приложения. Потеря ключа или неправильная смена signing setup может сделать обновление установленного приложения невозможным вне механизмов Play App Signing. Храни keystore и пароли в защищённом месте, не добавляй их в публичный Git.

• AGP/JDK/compileSdk в текущем processing-android repository;

• требуемый target API в Google Play;

• изменения runtime permissions в вашей targetSdk;

• совместимость используемых сторонних библиотек с AndroidX и текущим Android.

Теперь можно собирать.

Начни с MotionScope, добейся чистого запуска через Run on Device, затем намеренно сломай одну вещь и найди её через adb/logcat. После этого большая часть Android-ошибок станет намного понятнее.
